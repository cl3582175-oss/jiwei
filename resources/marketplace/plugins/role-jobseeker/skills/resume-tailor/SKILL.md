# 简历对岗

对岗改简历，是把已经做过的事写得让招聘者看得懂。缺少的能力要如实列出，数字和经历绝不能靠润色创造。

## 步骤

1. **拆清岗位要求**

   - 请用户给完整 JD 和简历或经历，确认目标岗位。
   - 分出明确必须项、加分项和从职责推断的隐含要求。
   - 隐含要求标“推断”，不能冒充招聘方的硬性条件。

2. **找真实经历素材**

   - 用 knowledge_search 与 memory_search 找已有项目和经历。
   - 候选素材用 note_read 或用户确认核对，区分个人贡献与团队结果。
   - 记录来源，记忆里模糊的信息先问本人，不直接写进简历。

3. **逐条对照岗位**

   - 每项标已满足、有素材但没写、缺口。
   - 写清证据来自哪段经历，缺口不能通过换词变成已满足。
   - 职位名称不同不等于能力不相关，按实际工作判断。

4. **改写可证明的条目**

   - 对有素材但没写的内容用 STAR：情境、任务、行动、结果。
   - 数字只能来自用户提供的信息，没有就留 [待补数字] 或真实定性结果。
   - 区分自己主导、参与和协助；不得扩大职责或移花接木成果。

5. **让用户核实措辞**

   - 逐句问是否准确，尤其是规模、日期、工具和成果归属。
   - 解释这句对应 JD 的哪条要求，删去无关夸张词。
   - 缺口给可执行弥补建议，说明学习计划尚不是已有经验。

6. **交付可复制版本**

   - 输出对照表、改写条目与缺口清单。
   - 需要保存时先确认目标笔记，再用 note_add_table 或 note_add_rows 提议写入。
   - 不自动投递、不外发简历，不声称修改后保证面试。

## 产出

- JD 要求与证据对照表。
- 每项状态：已满足、有素材但没写、缺口。
- 基于真实经历的 STAR 简历句。
- 缺数字保留 [待补数字]，不能假填。
- 缺口与弥补建议，保存走用户确认。

## 不要做

- 不要编造数字、雇主、学历或项目。
- 不要把团队成果全写成个人成果。
- 不要把推断的要求说成招聘方原话。
- 不要代用户发送或投递。

## 示例

用户：这个岗位要数据分析，帮我改简历。
助手：请给 JD 和你的真实经历。我会先对照要求，再找你已经做过但没写清的部分；没有证据的数字会留 [待补数字]。

用用户使用的语言回答。
