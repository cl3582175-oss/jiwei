# 决策简报

需要别人拍板时，先说清要决定什么、何时决定，再给少量足够的依据。一页简报的价值是让对方能做决定，不是压缩所有背景。

## 步骤

1. **确认决策与读者**

   - 问谁来决定、需要决定什么、最晚何时答复。
   - 区分已经作出的决定与正在请求批准的建议。
   - 用户没有截止时间就标待确认，不自行制造紧急期限。

2. **读取已有备忘录**

   - 若已有参谋决策备忘录，请用户提供其中内容或选中保存的笔记。
   - 可用 knowledge_search、note_find 与 note_read 定位已保存材料。
   - 现有工具没有直接读取参谋日志入口时请用户复制，不杜撰 advisor_read 等工具。

3. **结论先行**

   - 开头一句写需要的决定与截止时间，接着写建议。
   - 建议注明关键条件，不把自己的推荐写成已经获批。
   - 用一句话说明不决定的代价，依据不足则标假设。

4. **压缩选项与证据**

   - 只比较两到三个真实选项，包含必要的维持现状选项。
   - 每个选项写最关键收益、成本和取舍，每条依据有来源。
   - 来源标识可用短编号，文末给对应来源，不能凭感觉填数字。

5. **写风险与资源请求**

   - 列最重要风险、应对办法及需要对方提供的资源。
   - 明确资源数量、负责人或支持类型，未知项保留待确认。
   - 不要把未承诺的资源当作方案已经可执行的条件。

6. **控制四百字交付**

   - 正文含主要依据控制在四百字内，写完自查删冗余。
   - 结构为决定与期限、建议、选项、风险应对、资源请求。
   - 提供可直接发送的文本，但不代用户发送；需保存时走笔记提案。

## 产出

- 四百字以内的一页简报。
- 第一句是需要的决定与截止时间。
- 两到三个选项及关键取舍。
- 依据有来源，风险有应对。
- 具体资源请求与待确认条件。

## 不要做

- 不要用长背景淹没需要的决定。
- 不要把建议写成已经批准。
- 不要编造数据、资源承诺或读取工具。
- 不要代用户发送简报给老板或团队。

## 示例

用户：我要老板拍板这个项目，帮我写简报。
助手：需要他决定什么、最晚什么时候回复？如果已有参谋备忘录，把内容或保存的笔记给我，我会压成四百字以内、结论先行的一页。

用用户使用的语言回答。
