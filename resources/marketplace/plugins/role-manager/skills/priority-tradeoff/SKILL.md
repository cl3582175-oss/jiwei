# 取舍与停做清单

事情太多时，仅给全部任务重新排序还不够。必须看清哪些亲自做、哪些委托、哪些推迟，以及至少一件应该停下的事。

## 步骤

1. **列全正在做和想做的事**

   - 用 actions_list 与 goals_list 读取当前任务和目标。
   - 请用户补充未记录的工作、可用时间和必须履行的约束。
   - 去掉重复项，保留已有承诺的对象与期限。

2. **逐件看目标影响**

   - 说明这件事支持哪个已确认目标，以及不做会怎样。
   - 影响和紧急程度分开，不因为声音大就默认优先。
   - 缺目标依据时标待澄清，不能替团队编战略。

3. **判断亲自做与可逆性**

   - 逐件问是否只能用户本人做，是否存在可授权的人。
   - 写清委托需要的权限、交付标准和检查点。
   - 区分可逆试验与难以回退的决定，成本不只看执行时间。

4. **分成四类**

   - 明确列我亲自做、委托、推迟、停做四类。
   - 每项写分类理由和下一步，不把委托当成甩给未确认的人。
   - 推迟项写重新检查的条件，而不是永远搁置。

5. **提出至少一项停做候选**

   - 至少挑一件作为停做建议，说明代价、风险和要向谁说明。
   - 不能取消法定义务或已承诺事项时，改提范围缩减并明确需审批。
   - 最终停止与否由用户决定，不能调用工具直接删任务冒充取舍。

6. **整理可落地的决定**

   - 需要正式比较的事项建议转参谋“取舍与优先级”框架。
   - 用户确认后才用 action_create 提议必要的新行动，旧任务由用户确认处理。
   - 记录待确认负责人、日期和沟通对象，不声称已通知或已停做。

## 产出

- 我亲自做、委托、推迟、停做四类清单。
- 每项含目标影响、紧急程度、可委托性和可逆性。
- 至少一件停做候选及具体代价。
- 需要向谁说明与如何恢复的建议。
- 需正式决策的事项转参谋比较。

## 不要做

- 不要给所有事情都标最高优先级。
- 不要把委托直接当成他人已经承诺。
- 不要擅自取消义务、删除任务或发通知。
- 不要为了停做数量忽略不可逆风险。

## 示例

用户：这个季度事情太多，该聚焦什么？
助手：我先看行动项和目标，你再补上没记的事与可用时间。我们会分成亲自做、委托、推迟和停做，并至少找一件可以讨论停下的事。
