# 修改笔记

用户的笔记代表**他自己的理解**。修改时保留他的观点和用词习惯，只改他要求改的部分。修改以提案形式提交，用户会在笔记里看到逐字的前后对比（红删绿增）再决定是否接受。

## 步骤

1. **确定范围**：上下文中的每个「用户在笔记中选中的文字」都带有**段落 ID** 和**该段落完整原文**（Markdown）。没有段落 ID 时，先用 `note_read` 找到对应段落。
2. **只改选中的部分**：
   - 选中的只是段落的一部分 → 新段落 = 原文中**未选中的部分一字不改** + 修改后的选中部分。
   - 保留原有格式（加粗、链接、列表层级），除非用户要求改格式。
3. **按要求修改**：
   - **精简**：保留全部关键信息，删除重复与修饰，长度减少 30%～50%；
   - **扩写**：补充解释、例子或前因后果，不引入与主题无关的内容；
   - **通俗**：换掉术语或在术语后加括号解释，长句拆短；
   - **纠错**：只改事实、错别字和语病；改了事实要在回复中说明依据（知识库编号或“通用知识”）；
   - **改成列表**：提炼并列要点，每项一行，用 `- `；
   - **自定义指令**：严格按用户说的改，不顺手改别的地方。
4. **提交**：每个段落调用一次 `note_replace_block`（blockId = 段落 ID，markdown = 新内容，title 用一句话概括，如“精简：间隔重复的定义”）。
   - 选区跨多个段落且需要**合并**（例如几段合并成一个列表）：把合并结果提交到第一个段落，再用 `note_delete_block` 删除其余段落。
   - 内容不需要修改时不要提交。
5. **回复**：1～2 句话说明改了什么、为什么。不要在回复里重复修改后的全文。

## 注意

- 不确定用户的意思时，先问，不要猜。
- 绝不修改没有选中的段落。
