# 积微 v0.6.6 – v1.0：学习闭环与智能体平台（设计）

> 来源：2026-10-10 用户与 Claude 的四轮产品讨论，结论已全部确认。本文是 v0.6.6 到 v1.0 各版本实施说明书的设计依据。

## 0. 背景：现在缺什么

积微现在覆盖了学习的中段：阅读、听课、记笔记、批注、复习、费曼、复盘、错题、外文阅读。两头和整体仍有缺口：

| 缺口 | 表现 |
| --- | --- |
| **输入是被动的** | 知识只来自用户主动去找。AI 不会替你留意值得学的东西，也不会定时帮你看邮件、追踪动态。 |
| **没有输出** | 学到的知识没有被用起来：做不成视频、文章、课件，也不能辅助决策和行动。用不上的知识价值有限。 |
| **板块分散** | 十多个一级入口各自为政，没有地方回答“我今天该做什么”和“我最近进展如何”。 |
| **AI 入口分散** | AI 对话、工作区 AI 面板、就地答复卡片三个入口互不相通；“问问你的知识库”只能问答，不能办事。 |
| **封闭** | 不能被其他智能体使用，也不能使用其他软件，没有扩展机制。 |
| **数据安全** | 备份只覆盖知识库数据库，不含图片、录音和个人库，也没有恢复功能；录音以明文存放。 |

学习科学支持把输出纳入闭环：提取练习和生成效应说明，用出来比看进去更能巩固；迁移（在新情境中运用）是掌握的最高层级。产出本身就是学习最有效的一环，而不是学习之后的附加步骤。

## 1. 产品形态：三环 + 一个底座

```
            ┌──────────────── 积微助手（⌘J，随处可用）────────────────┐
            │      问（带出处的回答）· 办（跨模块执行）· 想（参谋）· 教（辅导）   │
            └─────────────────────────────────────────────────────────┘
  ┌──────────┐      ┌──────────────────────┐      ┌──────────────┐
  │ 环一 发现 │ ───→ │ 环二 学（现有）       │ ───→ │ 环三 用       │
  │ AI 任务   │      │ 读 听 记 批注 复习 错题 │      │ 创作工坊 参谋  │
  └──────────┘      └──────────────────────┘      └──────────────┘
        ↑                                               │
        └─── 产出暴露的缺口 → 复习卡片 / 新的学习主题 ←─────────┘
                       枢纽：方向 / 项目（由“学习目标”升级而来）
┌──────────────────────────── 智能体运行底座 ────────────────────────────┐
│ 触发器：定时 · 事件 · 手动      工具：内置 · MCP 客户端 · 连接器插件          │
│ 技能：内置 · 插件 · 导入的 Agent Skills      渲染：可视化块 · 动画/视频 · 导出 │
│ 策略：权限三级 · 提案确认 · 费用上限 · 隐私 · 审计                           │
└────────────────────────────────────────────────────────────────────┘
        对外：MCP 服务端（被 Claude、Cursor 等使用）· 插件市场
        底层：学习活动记录层（今日、计划、洞察、复盘的统一数据来源）
```

**用户群体：** 学生（中学、大学、考研）、研究者、职场人、内容创作者、教师。每个设计都要回答：这一群人用它时是什么样子。

**设计原则：**
1. **闭环优先。** 新功能必须接入“发现 → 学 → 用 → 回流”中的至少两环，孤立功能不做。
2. **克制推送。** 主动推荐限量，并说明理由；宁缺毋滥，防止变成又一个刷不完的信息流。
3. **可溯源。** 产出中的每个论断都能追到用户的笔记或资料，这是积微区别于通用 AI 写作工具的地方。
4. **辅助而非代写。** 学生默认用教练模式。
5. **用户掌控。** 写入要确认，对外操作每次确认，费用和权限可见、可撤销。
6. **本地优先。** 数据默认留在本机；任何离开本机的操作都要明示。

## 2. 信息架构（v0.6.7）

### 2.1 导航：五组 + 助手
```
[积微助手]   ← 强调色，⌘J 在任何页面唤起侧栏
[搜索]       ⌘K
───
今日         默认首页
收集         收件箱（含每日精选、任务结果）· 资料库 · 浏览器 · 录音
学习         笔记 · 复习（含错题本）· 费曼 · 知识图谱
创作         作品 · 参谋（v0.9 起）
计划         日历 · 时间线 · 方向与目标 · 回顾（复盘、洞察）
───
设置         含 AI 任务、MCP、插件、费用与权限中心、备份
```

**规则：**
- 一级入口只有五组，组内用二级标签切换。
- 现有快捷键保持可用，⌘1–⌘9 映射到对应的二级页面。
- 原来的“AI 对话”页并入积微助手，历史对话全部迁移。

### 2.2 「今日」：默认首页
它回答一个问题：今天该做什么。每张卡片都能直接操作，不放只供观看的数字。

- **AI 晨报：** 一段话，以助手的口吻，可以直接回复。例如：“今天 23 张卡片到期，错题本有 3 道变式题；昨晚的任务发现 2 篇与‘间隔效应’相关的新论文；导师的邮件需要回复。”
- **今日安排：** 时间轴，包括学习时段、复习、截止事项、日历事件。
- **待处理：** 复习与错题、每日精选、等确认的提案（来自任务、MCP、收件箱）、到期行动项。
- **进行中：** 正在写的作品，以及各方向的进度条。
- **顶栏：** 连续学习天数和缩小的热力图，沿用现有首页的数据。
- **顶部输入框：** “问积微，或交代一件事……”，输入后进入助手。

### 2.3 「计划」（v0.8）
- **日历（周 / 月）：**
  - 学习时段；
  - **复习负荷预测：** 用 FSRS 算出未来每天的到期卡片数，这是普通日历做不到的；
  - 考试与截止日；
  - 外部日历：v0.8 先支持 ICS 订阅（只读），MCP 就绪后再做双向同步。
- **时间线（甘特）：** 只给“方向 / 项目”用，按阶段、里程碑、任务展开，可以拖动改日期；每个阶段挂接对应的资料、笔记、错题和模拟卷。日常学习不用甘特图。
- **AI 排期：** 你给出目标、截止日和每周可投入的时间，AI 结合复习负荷生成计划，确认后写入日历。进度落后时，AI 主动提醒并给出调整方案。
- **按人群：**
  - **学生：** 考试倒计时、课表导入（ICS）、学期视图；
  - **职场人：** 项目里程碑、会议前的准备块。

### 2.4 「洞察」（v0.9，放在 计划 → 回顾 里）
每周回顾时看，按学习闭环分四段：

- **投入：** 各方向花了多少时间，按阅读、听课、复习、写作分开。
- **内化：** 掌握度变化、记忆保持率、错因趋势。
- **产出：** 作品数、知识运用率（被用进作品或决策的知识占比）。
- **成本：** AI 花费，按功能拆分。

招牌图是**知识漏斗**：发现 → 阅读 → 记下 → 掌握 → 运用，显示知识在哪一步流失。

## 3. 学习活动记录层（v0.6.7）

今日、计划、洞察、复盘、晨报都需要统一的数据来源。现在各模块的数据分散在各自的表里，热力图只统计笔记编辑次数。

- **新表 `activity_events`（知识库）：**
  - 字段：`id`、`at`、`kind`（read、listen、review、write、record、practice、create、decide……）、`direction_id`（可空）、`ref_type`、`ref_id`、`duration_ms`、`count`、`meta`（JSON）。
  - 按天聚合，另建 `activity_daily` 表或视图，供首页和看板读取。
- **时长统计：** 只统计窗口在前台、并且最近 60 秒内有键鼠或播放的时间，离开后自动暂停，不把挂机算作学习。
- **埋点：** 各模块在已有的“完成”节点写入事件：
  - 复习评分；
  - 资料阅读会话结束；
  - 录音结束；
  - 笔记编辑会话结束；
  - 错题练习；
  - 作品保存。
- **数据规则：** 不同步，可以在设置中清除；不发给模型，晨报只使用聚合后的数字。

## 4. 积微助手（v0.6.7 统一，v0.7 起逐步增强）

### 4.1 定位
从“问答窗口”升级为“学习伙伴兼执行者”，是智能体底座面向用户的那张脸。

| 能力 | 例子 | 版本 |
| --- | --- | --- |
| **问** | 基于你的知识回答，带出处 | 现有 |
| **办** | “把下周三的考试加进计划并排复习”“每天 8 点看邮箱”（建成 AI 任务）“把这周的错题出成一套卷子” | v0.7 / v0.8 |
| **想** | 参谋：决策备忘录，并记入决策日志 | v0.9 |
| **教** | 苏格拉底式辅导，对接费曼与教练模式 | 现有，整合进来 |

助手根据用户说的话自动判断属于哪类能力，不让用户手动选模式。

### 4.2 三种形态，共用一套对话、历史和记忆
1. **全屏助手页：**
   - 左侧对话，右侧“成果区”（计划表、文档草稿、图表、决策备忘录），可一键存为笔记、作品或任务；
   - 执行过程可见：用了什么工具、读了哪些资料、花了多少钱；
   - 长任务可以放到后台继续，完成后通知。
2. **随处唤起的侧栏（⌘J）：** 由现有的工作区 AI 面板推广而来，自动带上当前页面的上下文（今日、日历、错题、作品……），可以一键展开为全屏页继续聊。
3. **就地卡片：** 保留选区浮条，增加“转到助手继续问”。

### 4.3 主动性
晨报、周日伙伴检查、任务结果、计划落后提醒，都以助手消息的形式出现在「今日」，你可以直接回复。

## 5. 智能体运行底座（v0.7）

| 组件 | 说明 |
| --- | --- |
| **工具注册表** | 统一描述内置工具（现有的 `knowledge_search`、`note_*`、`browser_*`、`memory_*` 等）、MCP 工具和连接器插件。每个工具声明：输入输出契约（zod）、副作用等级（read、write、external）、费用估算、隐私要求。借鉴 monid 的 discover / inspect / run 三个动作，工具多时先检索再选用。 |
| **执行器** | 多步工具调用循环；每一步记录轨迹；可取消；可放到后台；有超时与步数上限。 |
| **策略引擎** | **权限三级：** read 自动；write 变成提案等用户确认；external（发邮件、发消息、提交表单）每次确认，不能授权为自动。<br>**费用：** 单次、每日、每月上限，超限暂停并询问。<br>**隐私：** 标为“仅本地”或“不给 AI”的数据不进入任何外部调用。<br>**提示注入防护：** 工具返回的网页、邮件、文件内容一律作为数据封装；读取不可信内容的那一步，不能直接触发 external 动作。 |
| **审计日志** | 每次工具调用的时间、调用方（助手、任务或 MCP 客户端）、工具、参数摘要、结果、费用，可查询、可导出、可清除。 |
| **费用与权限中心** | 设置里的一页：本月各项花费、哪些客户端和插件有什么权限、最近做了什么，都可以撤销。 |

## 6. MCP 双向（v0.7）

### 6.1 积微作为 MCP 服务端
- **工具：**
  - `search_knowledge`、`read_note`、`read_source`、`list_notes`；
  - `get_due_reviews`、`get_mastery`；
  - `add_to_inbox`、`add_source`；
  - `propose_note_edit`：改笔记只生成提案，在积微里确认后才生效。
- **资源：** 笔记、资料（只读）。**提示词：** 技能。
- **传输：**
  - **stdio：** 随应用附带一个小命令行程序，经本机套接字连接正在运行的积微；
  - **Streamable HTTP：** 只监听 127.0.0.1，需要令牌。
- **权限：**
  - 每个客户端单独授权，默认只读；
  - “仅本地”和“不给 AI”的内容永不对外；
  - 每次调用记入审计日志，随时可以撤销。
- **价值：** Claude、Cursor 等工具都能把积微当作长期记忆来用。

### 6.2 积微作为 MCP 客户端
- **传输：** 支持 stdio 和远程（Streamable HTTP + OAuth 2.1，按 MCP 规范）；用官方 TypeScript SDK 实现。
- **使用范围：** 助手、AI 任务、创作工坊、参谋。
- **每个工具单独设策略：** 自动 / 每次询问 / 禁止。有副作用的工具默认“每次询问”。外部工具返回的内容一律作为数据。
- **凭证：** 存在系统钥匙串（safeStorage）。
- **常见用途：** Gmail、Outlook、日历、飞书、Notion、GitHub、Figma、文件系统、Blender、Excel。

## 7. AI 任务（v0.8）

**一个任务 = 触发 + 指令 + 可用工具 + 结果去向。**

| 部分 | 内容 |
| --- | --- |
| 触发 | **定时：** 每天、每周、工作日、自定义。**事件：** 新邮件、网页更新、文件夹出现新文件、日历事件前 N 分钟、错题累计 N 道、目标临近截止。**手动。** |
| 指令 | 自然语言 |
| 可用工具 | 显式勾选（邮箱、搜索、浏览器、知识库、某个 MCP 工具……），只能用勾选的工具 |
| 结果去向 | 收件箱、晨报、系统通知、笔记（提案）、待办 |

- **创建：** 用一句话描述，AI 解析成上面四项，你确认后保存。任务列表显示运行记录、费用和结果，可以暂停、修改、手动运行。
- **邮箱：**
  - 通用 IMAP，覆盖 QQ、163、Outlook 的授权码；
  - Gmail 和飞书走 MCP；
  - 凭证存在钥匙串；
  - 邮件内容一律作为不可信数据，读邮件的任务不能直接执行 external 动作。
- **运行条件：**
  - 电脑开着时运行，可以开机自启、常驻托盘；
  - 错过的任务在开机后补跑，并标注“延迟执行”；
  - 云端运行器以后再考虑（数据会离开本机）。
- **预置任务配方：**
  - 每日精选；
  - 邮件要点；
  - 晚间错题变式；
  - 考前每日计划；
  - 每周行业简报；
  - arXiv 新论文；
  - 会议前准备；
  - 周日伙伴检查。

## 8. 发现（v0.8）

- **入口：** 收件箱新增“精选”标签，不另开一级入口。
- **找什么：** 方向与目标、掌握度地图的薄弱点、错题的高频错因、正在学的概念的前沿进展。
- **从哪里找：** 订阅源（RSS/Atom、arXiv、B 站或 YouTube 频道、播客、网站更新），以及可选的搜索服务（博查、Tavily、Brave，或者 monid 插件；用户自己填 key）。
- **怎么筛：**
  - 先用向量和知识库去重，已经掌握的内容不推；
  - 再由 AI 批量打分：相关性、新颖度、可信度、深度、所需时长；
  - 有意混入少量反方观点和跨领域内容，防止信息茧房；
  - 在 DeepSeek 半价时段运行，设每日预算上限。
- **怎么推：**
  - 每天最多 5 条；
  - 每条注明：为什么推荐给你、和你的哪篇笔记相关、补的是哪个缺口、读完大约要多久。
- **你怎么处理：** 读（在内置浏览器里，带 AI 伴读）、存为资料、稍后、不感兴趣。系统根据这些反馈学习你的偏好。
- **主动模式：**
  - **学习路径：** 你给一个方向，AI 编一份由浅到深的资源路线；
  - **错题补救：** 针对错题知识点去找讲解和练习。
- **每日学习播客（可选）：** 把精选和待复习内容用语音合成做成约 10 分钟的音频。
- **按人群：**
  - **学生：** 以考纲和教材为准，侧重讲解与练习，不推新闻；
  - **职场人：** 行业动态和竞品变化。

## 9. 创作工坊（v0.9）

### 9.1 产出全景
| 类别 | 形式 |
| --- | --- |
| 讲解分享 | 知识讲解视频（口播稿、分镜、字幕）、双人对谈音频、课件 PPT、图文长文、知识卡片、培训材料 |
| 写作 | 读书笔记、书评、文献综述、论文章节、研究报告、方案、周报 |
| 分析 | 行业与竞品分析、SWOT、专题问答 |
| 决策 | 决策备忘录、方案比较、事前验尸（见第 11 节参谋） |
| 行动 | 行动计划、操作清单、习惯计划、项目计划 |
| 应试求职 | 冲刺卷、答题模板、面试问答库（STAR）、简历要点、作品集 |
| 教别人 | 出题、讲解提纲、答疑 |
| 长期作品 | 课程设计、书稿、公开的个人知识网站 |

第一批（v0.9）做三种：**讲解视频、图文长文、课件 PPT**。其余类型由模板和角色包陆续补充。

### 9.2 统一流程
1. **选题：** AI 根据你掌握得好的知识和目标受众推荐选题。
2. **素材：** 自动从你的笔记、批注、资料、错题收集素材，每条都带出处。
3. **结构：** 生成提纲，你来调整。
4. **起草：** 选协作模式：教练（只给提纲、追问、批改）/ 共写 / 代写初稿。学生默认教练模式。写作风格可以学习你过去的文字。
5. **打磨：** 用“受众视角”挑刺；逐条核对事实是否与资料一致；标出讲不清的地方。
6. **成品：** 导出 Markdown、Word、PPT、SRT 字幕、知识卡片图片、视频分镜表。讲解视频可以导出为 QFL-VIDEO-STUDIO 的 `script.json`（D/P 双人轮次）格式，接入用户现有的视频生产流程。
7. **回流：**
   - 讲不清的地方生成复习卡片；
   - 用到的知识提升掌握度，并标记为“已迁移”；
   - 记录作品发布在哪里；
   - 写一次作品复盘。

### 9.3 数据
- **`works` 表：** 类型、方向、状态、模板、协作模式、导出记录、发布记录；草稿用 Yjs 文档，复用笔记编辑器。
- **`work_sources`：** 作品与素材的引用关系，用于溯源和计算“知识运用率”。

## 10. 可视化与动画引擎

现状：助手已有 `note_add_chart`、`note_add_diagram`、`note_add_timeline`、`note_add_mindmap`、`note_add_interactive` 等工具，第 0 层已有部分基础。

### 10.1 三层
| 层 | 引擎 | 用途 | 安装 | 版本 |
| --- | --- | --- | --- | --- |
| 0 即时图示 | KaTeX（已有）、Mermaid、Vega-Lite、function-plot 或 JSXGraph、Markmap | 笔记里的“可视化块”；错题的可拖动几何图与函数图；复习卡片配图 | 预装 | v0.9 补全 |
| 1 视频与动画 | 默认用 Motion Canvas 或 Revideo（MIT）；Remotion 作为插件（个人和 3 人以内公司免费，更大公司需购买许可，由用户安装时确认） | 讲解视频、口播加字幕、知识卡片动画、PPT 动效 | 插件 | v0.9 |
| 2 数学动画 | Manim Community（MIT） | 公式推导、函数变换、几何证明 | 插件，用 uv 建独立 Python 环境，配 TinyTeX，首次约 300–500 MB | v0.10 |

视频合成复用现有的 ffmpeg；配音用服务商的语音合成或本地语音模型（插件）。

### 10.2 用在哪里
- **笔记：** AI 解释时自动配图，也可以说“把这段画成流程图”。
- **错题解析：** 可拖动的几何图、函数图像变换动画。
- **复习卡片：** 卡片里可以放图。
- **讲明白：** 可选“带动画讲解”，生成十几秒的动画。
- **创作工坊：** 讲解视频按“分镜 → 每镜动画 → 配音 → 字幕 → 合成”的流程生成；知识卡片渲染成图片；PPT 加动效。

### 10.3 让 AI 稳定地用好
1. **模板优先：** 每个引擎配一套参数化模板，例如公式逐步推导、函数平移伸缩、几何辅助线生长、时间线、数据条形图、概念关系展开。AI 只需要填参数；复杂需求才让 AI 写自由代码。
2. **每个引擎一个技能：** `SKILL.md` 包含 API 速查、积微视觉规范（配色、字体、节奏）和常见错误。
3. **自动校验：** 渲染失败时把报错交回 AI 修正，最多 3 次；渲染成功后抽几帧给看图模型检查文字重叠、出界和公式；通过后才给用户预览。
4. **对话式修改：** “第二步放慢一点”“换成深色背景”。
5. **沙箱：** AI 生成的代码在独立子进程里运行，只能写临时目录、不能联网、有超时限制；Python 先做静态检查，禁止 `os`、`subprocess`、`socket` 一类模块；JS 引擎在隔离的无网络 BrowserWindow 中渲染。

## 11. 参谋与决策日志（v0.9）

- **提问：** 你提出一个真实问题（“要不要换岗”“方案 A 还是 B”）。
- **找依据：** 先在你的知识库里找，必要时联网补充。
- **套框架：** 决策矩阵、关键假设、事前验尸、二阶影响、反方意见。
- **出备忘录：** 包含选项、证据（带出处）、风险和建议。
- **决策日志：** 记下当时的预期，并设一个回看日期；到期后进入复盘，对照实际结果，校准你的判断力。决策日志接入现有的洞见与认知成长轨迹。

## 12. 角色工具包（v0.10）

借鉴 Anthropic knowledge-work-plugins 按角色打包的思路。每个包包含：信息源清单、产出模板、分析框架、技能、AI 任务配方。

预置包例如：中学生 · 考试、大学生 · 科研、考研、产品经理、教师、内容创作者、管理者、求职者。用户可以安装、修改，也可以自己做一个。

## 13. 插件市场（v0.10）

### 13.1 两类插件
| 类型 | 内容 | 审核 | 运行 |
| --- | --- | --- | --- |
| **声明式** | 技能、角色包、作品模板、视角、任务配方、可视化模板、信息源清单 | 轻审核；用户可一键分享 | 不执行代码 |
| **代码** | 连接器、渲染引擎、MCP 服务器、导入导出器 | 签名、权限声明、人工审核 | 独立进程，只拥有声明过的权限 |

### 13.2 格式
`jiwei-plugin.json` 声明：

- 基本信息：`id`、`version`、`publisher`、`engines.jiwei`；
- **权限：** 网络域名、文件、钥匙串、费用；
- **贡献内容：** skills、templates、lenses、taskRecipes、connectors、mcpServers、renderers、sources。

安装前向用户展示所需权限；支持更新和回滚。

**连接器插件**采用 monid 的模式：声明式 endpoint（zod 契约）、录制好的回放测试、凭证在传输层注入（插件代码拿不到明文 key）、出错时拒绝执行、每次调用声明费用。

### 13.3 兼容外部生态
直接导入 Anthropic Agent Skills（`SKILL.md`，与积微的技能格式基本一致）和 knowledge-work-plugins（技能 + 命令 + MCP 配置）。开放生态里的大量现成内容，第一天就能用。

### 13.4 市场
- **起步：** 用一个 GitHub 仓库做插件索引，通过 PR 审核，与 Homebrew 的模式相同。
- **应用内：** 浏览、搜索、评分、安装、更新、卸载、回滚。
- **用户分享：** 支持“把我的技能或角色包发布为插件”。付费插件以后再考虑。

### 13.5 monid
作为可选插件接入：用户填一个 monid key，就能使用 2000 多个工具（搜索、网页抓取、语音合成、视频生成等）。代价是数据会发给第三方并产生费用，所以不作为默认。

## 14. 备份恢复与录音加密（v0.6.6）

详见 `docs/specs/v0.6.6-backup-and-safety.md`。要点：
- **完整备份：** 包括知识库、个人库、素材、录音和清单校验，可以导出为单个 `.jiwei` 文件。
- **安全恢复：** 默认恢复为新的知识库，不覆盖当前的知识库。
- **录音加密：** 分块 AES-256-GCM，支持拖动播放；用恢复码在另一台电脑上恢复。

## 15. 安全、隐私与费用总则

1. 网页、邮件、文件、工具返回的内容一律作为数据，不作为指令。
2. 写入走提案，对外操作每次确认，费用超限暂停。
3. “仅本地”和“不给 AI”的数据不进入任何外部调用，也不通过 MCP 服务端对外。
4. 凭证只存放在系统钥匙串，不写日志，不进入备份明文。
5. 所有自动化行为都写入审计日志，可以撤销。
6. 插件只拥有声明过的权限；代码插件在独立进程中运行。

## 18. 已确认的决策
1. 默认视频引擎用 MIT 许可的 Motion Canvas 或 Revideo，Remotion 只做插件。
2. Manim 按需安装，首次约 300–500 MB。
3. 插件市场先用 GitHub 仓库做索引，PR 审核。
4. monid 作为可选插件，不作为默认。
5. 智能体底座和 MCP 双向放在 v0.7。
6. 导航按“今日 · 收集 · 学习 · 创作 · 计划”五组重组，加顶部的积微助手；「今日」为默认首页。
7. v0.6.6（备份与安全）和 v0.6.7（架构重组）分成两个版本。
8. 外部日历先支持 ICS 订阅导入，双向同步等 MCP 就绪后再做。
9. AI 对话升级为积微助手，原“AI 对话”页并入。
