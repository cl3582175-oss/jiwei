# 积微 v0.13 – v0.17：联网研究、深度研究与分析工作台（设计）

> 状态：设计稿，待确认。日期：2026-10-13。
> 范围：联网搜索与搜索路由、深度研究引擎、数据分析工作台、本地大模型与模型路由，以及它们怎样融进积微现有的知识库、参谋、创作工坊、AI 任务和学习闭环。

---

## 0. 结论先行

1. **积微的研究能力不做成“聊天加一个搜索按钮”。** 它是一条有状态的工作流：澄清 → 计划（用户可改）→ 先查你自己的知识库 → 并行调查 → 交叉核验 → 分节撰写 → 引用审计 → 回流成笔记、洞见、行动项和定期追踪。每一步都落库，中途退出后可以续跑，用户可以随时插话改方向。
2. **差异化在于“你的知识 + 公开世界”。** 通用深度研究产品只会搜外面。积微先读你的笔记、资料、方向和决策日志，知道你已经知道什么、在为什么做决定，再去外面补缺口。报告里专门有一节写“和你已有知识的关系”：哪些印证了，哪些推翻了，哪些笔记该标为存疑或过时。
3. **证据先于结论。** 新增“证据库”（Evidence Ledger）：每条证据都是网页或论文快照里的一段原文，用 W3C TextQuote 锚定（积微批注本来就用这套）。报告的每句事实陈述都指向证据。点开引用，看到的是保存下来的原文并高亮那句话，不会出现“链接打开后找不到这句话”。
4. **搜索走积微自己的“信息获取网关”，不绑定某一家模型。** 网关统一管理多个搜索后端：国内与国际通用搜索、学术库、开放数据、知识库、内置浏览器和 MCP。它负责路由、回退、缓存、去重、重排、配额与费用。厂商自带搜索（Claude、OpenAI、Gemini、通义、智谱）只作为可选后端，因为这类搜索换模型就失效，有的还不能和自定义工具同时使用。哪些入口能联网由用途白名单决定；助手默认“自动”联网，先查知识库再判断；知识库与网页结果统一到段落、用同一个向量模型打分，再按名额合并，冲突按问题类型裁决（§4.6–4.9）。
5. **核验是独立的一步，不靠写作者自觉。** 2026 年的研究一再说明：智能体常常查到了正确的记录却提前停下，转而相信一篇“像答案”的文档；而且通常只核对带引用标记的句子。积微为此加三道关：关键结论至少两个独立来源、针对每条关键结论做反向搜索、由另一个模型逐句审计全文（包括没标引用的句子）。
6. **数据分析要能真正算。** 新增分析工作台：默认用 Pyodide（WebAssembly 版 Python，天然隔离、三平台一致、体积小），重任务可选本机 Python 环境（复用 Manim 的 micromamba 安装管线）。流程强制先做数据画像，报告里的每个数字都链接到算出它的代码单元，并可以复算。
7. **本地大模型由积微自己运行。** 在现有的 llama-server 附属进程（现在只跑向量模型）上扩展对话模型和重排模型。安装时检测硬件，推荐合适的模型并做一次工具调用自测。弱模型和本地模型由代码编排流程、模型只做小决策（“代码编排，模型填空”）；强模型由模型自己编排。可选“混合隐私模式”：私密内容只交给本地模型阅读，云端模型只看到本地模型整理后的摘要。
8. **按难度分档花钱。** 快答、调研、深度研究、持续追踪四档。多智能体研究的 token 用量大约是普通对话的 15 倍，所以只在值得的时候用，开始前显示用量档位和上限，过程中实时显示花费，随时可以暂停。
9. **v0.13 先打地基。** 先做信息获取网关、助手联网（快答）和模型路由的抽象层；随后依次是 v0.14 深度研究、v0.15 分析工作台与三类人群的工作流、v0.16 本地大模型、v0.17 持续追踪与学术深化。

## 1. 现状盘点：已有什么，缺什么

### 1.1 能直接复用的

|---|---|---|
| 搜索服务（博查 / Tavily / Brave，单选一个） | `services/discover/search.ts` | 改造成网关的三个后端；目前只有「发现」在用，助手不能搜 |
| 网页正文抽取（Readability）、按域名排队限速、重定向校验、敏感网站拦截 | `webText.ts`、`externalFetch.ts`、`lib/browserPolicy.ts` | 读取管线的第一级 |

| 费用记账与上限（每次运行、每日、每月） | `agent/usage.ts`、`model.ts` 中的 `meter` | 研究预算、实时花费 |

| EmbeddingGemma 2 本地向量（llama-server） | `ai/localEmbedding.ts` | 网页段落筛选、语义去重、轻量重排；本地对话模型复用同一套进程管理 |
| 技能（Agent Skills，按模型档位过滤） | `ai/skills.ts`、`resources/skills` | 文献综述、市场分析等方法论以技能形式交付 |
| 参谋与决策日志、创作工坊、AI 任务、发现、错题与复习 | 各自服务 | 研究的上游与下游 |
| 资料分段 + W3C 选择器、批注 | `source_segments`、`annotations` | 网页快照入库后，引用可以精确到句 |

| 可视化（Vega-Lite、Mermaid、ECharts、函数图） | `shared/embeds/visuals.ts` | 分析图表按积微主题渲染 |

### 1.2 缺的

1. 助手没有 `web_search` / `read_url` 工具；只有用户先打开了浏览器标签页，才有 `browser_*` 只读工具。
2. 只能启用一个搜索服务，没有路由、回退、缓存，也没有学术和数据来源。
3. 没有研究流程：没有计划、并行、证据库、核验和长报告撰写。现有循环最多 10 步（`MAX_STEPS`），历史只带原话。
4. 没有代码执行，数据分析只能靠模型心算。
5. 本地模型只能通过 Ollama 接入，没有自带运行时，也没有针对弱模型的调度方式。
6. 模型选择是“一次对话一个模型”，没有按角色分工（计划 / 调查 / 抽取 / 核验 / 撰写）。

## 2. 调研结论与设计启示

下表每一行都对应后文的一个设计决定。来源列在文末。

| # | 发现 | 设计启示 |
|---|---|---|
| R1 | Anthropic 的研究系统采用“主智能体 + 并行子智能体”。多智能体版本比单智能体高 90.2%（内部评测）。在 BrowseComp 上，token 用量能解释约 80% 的表现差异；多智能体的 token 用量约为普通对话的 15 倍。 | 深度研究用编排 + 并行调查员；**按难度分档**，不让简单问题烧钱（§5.1）。 |
| R2 | 同一来源的经验：按问题复杂度给出明确的投入规则（简单问题 1 个智能体、3–10 次工具调用；比较类 2–4 个子智能体；复杂研究 10 个以上）；子任务说明要写清目标、输出格式、工具和边界；先用宽泛的短查询，再逐步收窄；子智能体每次拿到工具结果后思考一下。 | 把投入规则写进计划器；调查员任务书有固定格式（§5.4）。 |
| R3 | 同一来源：计划要存到上下文之外；子智能体把产出写到外部存储，只回传引用，避免“传话游戏”；引用由单独的 CitationAgent 在最后处理。 | 证据库 + 研究工作区；引用审计独立成一步（§5.3、§5.6）。 |
| R4 | 同一来源的评测方法：一开始约 20 条真实问题就够；用单个评审模型按五项打分（事实准确、引用准确、完整性、来源质量、工具效率）；人工检查发现智能体偏爱 SEO 内容农场，加了来源质量规则才改善。 | 内置评测集与评分规则；来源可信度打分（§9、§5.5）。 |
| R5 | WebWeaver（ICLR 2026）：计划器交替进行“找证据”和“改大纲”，大纲链接到证据库；写作者按节写，每节只取被引用的证据，以缓解长上下文问题和引用幻觉。 | 动态大纲 + 分节撰写（§5.6）。 |
| R6 | Gemini Deep Research API（2026 年 7 月公开预览）支持协作式计划：先返回研究计划，开发者可以多轮修改，确认后才执行。 | 计划默认给用户看、可改，也可以“直接开始”（§5.2）。 |

| R8 | DEER（2026）：现有来源核验通常只看带引用标记的句子，没标引用的陈述没人查。DeepHalluBench：幻觉会沿着研究过程逐步传递。 | 引用审计覆盖全文每一句事实陈述；中间步骤也留痕（§5.6）。 |
| R9 | DeepResearch Bench 的 FACT 指标：抽出“陈述—URL”对，逐对判断来源是否支持陈述，得到引用准确率。不同系统差异很大（约 39% 到 94%）。 | 用同样的方法在产品里给每份报告算“引用支持率”，并用于评测（§9）。 |
| R10 | 数据智能体：DABstep 最难部分的最好成绩约 15%；2026 年多项研究指出几类常见错误：误读任务约束、没把数据看全就下结论、依赖先验而不用工具核对，以及能运行但逻辑悄悄出错、看起来合理的结果。 | 分析流程强制数据画像、断言与对账检查；数字可追溯到代码；关键数字复算（§6）。 |
| R11 | 搜索 API 没有公认最好的；价格、免费额度在 2026 年变化多次（例如 Brave 调整了免费层，Kimi 的 `$web_search` 于 2026-10-20 下线，改为独立的 search / fetch 接口）。厂商自带搜索换模型就失效；Gemini 的 Google 搜索不能和自定义函数工具同时用。 | 搜索由积微自己的网关管理，后端可插拔，目录可远程更新；厂商自带搜索只是可选后端（§4）。 |

| R13 | 自建 SearXNG 能让本地智能体保有隐私，但会遇到上游限流和封禁，需要调整限流器、配 Redis。 | SearXNG 作为“高级 / 全本地”选项，不作为默认（§4.2）。 |

| R17 | Minions（Stanford）：本地小模型读长文档，云端大模型只负责拆分和汇总，可以以约 1/5.7 的云端花费，达到云端单独做时 97.9% 的效果。 | “混合隐私模式”：私密内容只交给本地模型读（§8.4）。 |
| R18 | 上下文工程（Anthropic、Manus）：系统提示前缀保持稳定以命中 KV 缓存；每步把待办和计划重写在上下文末尾；把长工具输出放到文件里，只给模型引用；工具少而原子化（Manus 少于 20 个）；子智能体回传 1000–2000 token 的摘要。 | 积微已经在做前缀缓存；研究引擎沿用这些做法（§5.7）。 |
| R19 | 预测：AIA Forecaster 用“检索高质量新闻 + 多份独立预测由主管调和 + 统计校准”，在 ForecastBench 上与超级预测者持平。 | 参谋的“预测与概率”部分采用：多份独立估计 → 调和 → 结合基准率，并在决策日志里跟踪校准（§7.3）。 |
| R20 | llama-server 已有路由模式（一个端点管理多个模型，按需加载，LRU 换出，每个模型独立进程）和重排接口（`--reranking`）。 | 本地对话、向量、重排模型由同一个进程管理器托管（§8.1）。 |

## 3. 设计原则

1. **先懂你，再搜外面。** 每次研究都先查知识库和记忆，只把真正的缺口拿去外面搜。
2. **证据先于结论。** 先有证据，再有论断，最后才是文字。没有证据的句子必须标明是推断或通用知识。
3. **过程可见、可干预、可复现。** 计划、检索式、读过的页面、取舍理由都留存；中途可以插话；之后可以重跑和对比。
4. **能力分档，平滑降级。** 强模型、普通模型和本地模型都能用，只是深度不同。弱模型由代码兜住流程，绝不能输出看似完整、其实没核验过的报告。
5. **花钱有数。** 开始前预估用量档位，运行中显示实时花费，并设上限。界面文案里不写具体金额承诺。
6. **外部内容只当数据。** 沿用 `<external-data>`；调查员没有任何写入工具；最终写入一律走提案。
7. **成果回流。** 研究的终点不是一份报告，而是你的知识库更完整、判断更准：笔记、资料、洞见、复习卡片、行动项和定期追踪。

## 4. 信息获取网关（联网搜索与路由）

### 4.1 总体结构

```
          助手快答 · 研究引擎 · 参谋 · 发现 · AI 任务 · 创作工坊
                               │
                ┌──────────────▼──────────────┐
                │        信息获取网关          │
                │  意图识别 → 路由 → 并发 →    │
                │  回退/熔断 → 缓存 → 去重 →   │
                │  重排 → 记账 → 隐私检查      │
                └──┬──────┬──────┬──────┬─────┘
          通用搜索  学术库  开放数据  你的数据(知识库/订阅/浏览器/MCP)
                               │
                      读取管线（抓取 → 渲染 → PDF → 快照）
```

网关在主进程，放在 `services/retrieval/`：`gateway.ts`、`backends/*.ts`、`router.ts`、`reader.ts`、`cache.ts`。`discover/search.ts` 迁过去，现有调用方式保持兼容。

### 4.2 后端与能力描述

每个后端都声明自己的能力，路由只看这份声明，不写死某家：

```ts
interface SearchBackend {
  id: string                       // 'bocha' | 'zhipu' | 'iqs' | 'kimi' | 'tavily' | 'brave' | 'exa' | 'serper' | 'searxng' | 'openalex' | ...
  kind: 'web' | 'news' | 'academic' | 'data' | 'native'
  langs: ('zh' | 'en' | '*')[]     // 擅长的语言
  freshness: boolean               // 支持时间范围
  returnsContent: boolean          // 是否直接返回正文（省一次读取）
  site: boolean                    // 支持站点限定
  cost: { unit: 'call' | 'credit'; tier: 'free' | 'low' | 'mid' | 'high' }
  privacy: 'local' | 'self-hosted' | 'third-party'
  needsKey: boolean
  limits?: { rpm?: number; daily?: number }
  search(q: Query, signal): Promise<RawResult[]>
}
```

首批后端如下。具体价格和免费额度变动频繁，不写进代码，放在可远程更新的目录里，界面上只显示“免费 / 低 / 中 / 高”档位。

| 类别 | 后端 | 说明 |
|---|---|---|
| 中文通用 | 博查（已有）、智谱 Web Search、阿里云 IQS、Kimi search / fetch | 中文问题默认；国内网络可直连 |
| 国际通用 | Tavily（已有）、Brave（已有）、Exa、Serper | 英文问题默认；Exa 适合按语义描述找内容，Serper 返回 Google 结果页 |
| 自建 / 全本地 | SearXNG（填写自己的实例地址） | 隐私优先的高级选项；提示用户需要调整限流器 |
| 厂商自带 | Claude `web_search` / `web_fetch`、OpenAI `web_search`、Gemini `googleSearch`、通义、智谱 | 仅当当前模型来自该厂商时可选；网关把返回的引用解析成统一格式，写入证据库。Gemini 的 Google 搜索不能与函数工具同时使用，只用于“快答”档 |
| 学术（免 Key 或免费额度） | OpenAlex、Semantic Scholar、arXiv、Crossref、PubMed、Unpaywall（找开放获取全文） | 默认开启，**零配置就有价值**；按各自限速排队 |
| 开放数据 | World Bank、IMF、OECD、Eurostat、FRED（需 Key）、Our World in Data | 以“数据连接器”形式提供，返回表格而不是网页 |
| 你的数据 | 知识库、订阅源条目、内置浏览器已打开的标签页、MCP 服务器 | 知识库永远第一个查；浏览器标签页读取沿用现有的敏感页面规则 |

更多垂直来源（专利、财报、法规、中文统计数据、行业数据库）通过插件市场里的 MCP 连接器接入，不内置，避免安装包膨胀。

**不做的事：** 不在后台用内置浏览器自动抓取搜索引擎结果页（违反服务条款，还会触发人机验证），不绕过人机验证和付费墙。需要登录才能看的内容，只读用户自己打开的标签页，而且要先征得同意。

### 4.3 路由

**输入：** 查询文本，加上调用方给出的提示：类型（新闻 / 学术 / 数据 / 操作指南 / 产品 / 政策法规）、时效、语言、站点、预算档位。

**意图识别分两层：**
1. 规则先判断：查询语言、是否含时间词（“最新”“2026”“本周”）、是否像 DOI 或论文标题、是否是政策法规类词汇。
2. 研究引擎的计划器在给每个子问题出检索策略时，会直接标好类型和时效，这样不需要额外调用模型。快答档只用规则。

**路由表（默认，用户可以调整顺序）：**

| 类型 | 中文查询 | 英文查询 |
|---|---|---|
| 通用 | 博查 → 智谱 → IQS | Tavily → Brave → Exa |
| 新闻 / 时效 | 带时间范围的通用后端 | Brave（新闻）→ Tavily |
| 学术 | OpenAlex + Semantic Scholar 并发；中文学术再加通用搜索（文献站点优先） | OpenAlex + Semantic Scholar + arXiv / PubMed（按领域） |
| 数据 | 数据连接器 → 通用搜索找官方统计页 | 同左 |
| 已配置的厂商自带 | 当前模型属于该厂商，且处于快答档 | 同左 |

**并发与扇出：** 快答档每次 1 个后端。调研和深度研究档里，一个子问题最多同时查 2 个互补的后端（例如通用加学术）。结果按规范化 URL 去重，再用 RRF 合并。

**回退与熔断：** 遇到错误、429 或空结果时，换路由表里的下一个后端。同一后端连续失败 3 次，熔断 10 分钟。每个后端独立排队、限速，沿用 `externalFetch` 按域名排队的做法。

**缓存：** 新表 `search_cache`，键为（规范化查询、后端、时效、站点），有效期按时效决定：新闻 1 小时、通用 7 天、学术 30 天。无痕对话不写缓存。

**重排：** 先用已有的 EmbeddingGemma 计算查询和标题加摘要的相似度，并做语义去重（不需要新模型）。装了本地重排模型（§8）后，深度研究档改用重排模型。

**记账：** 每次搜索、抓取都记到 `usage`，`purpose` 字段写明是快答还是哪次研究。「费用与权限中心」新增“搜索与抓取”分类。

### 4.4 读取管线

`read_url(url, focus?)` 按以下顺序逐级尝试：

1. **直接抓取：** `externalFetch` 加 Readability（现有）。
2. **渲染：** 正文太短（少于 500 字）或疑似需要 JS 时，用一个隐藏的 WebContents 渲染。它使用独立分区、不带 Cookie、禁止下载和弹窗，等页面稳定后取正文。
3. **PDF：** 用资料库已有的 PDF 解析和识别管线（扫描页也能读）。
4. **可选托管读取：** Jina Reader、Kimi fetch、Firecrawl，作为后端可选。

读到的内容要做三件事：

- **快照：** 正文按内容寻址存进素材仓库（`assets/`），记下获取时间。之后的引用都指向快照，原网页改了或下线了，引用照样可以打开。快照默认只保存在研究工作区里，用户选择“导入资料库”后才成为正式资料，进入检索。
- **段落筛选：** 长页面先切段（复用 `chunks` 的切法），用 `focus` 或当前子问题做向量相似度，只把最相关的 6–10 段交给模型，并附上段落编号。模型需要更多时可以要“下一批”。这一步对本地小模型尤其关键。
- **清洗与标记：** 去掉隐藏元素和零宽字符，标出疑似对 AI 下指令的文字（例如“忽略以上指令”），在 `<external-data>` 里加一个 `suspicious` 属性。

### 4.5 隐私

- 标为“不给 AI”的笔记和资料，内容绝不进入搜索查询。计划器生成的查询要经过一道检查：查询里如果出现了这类内容中特有的词组，就丢弃这条查询，并重新生成。
- 每次对话都有“联网”开关，默认跟随设置。无痕对话可以联网，但不写缓存、不保存快照。
- “谨慎模式”（可选）：外发查询先列给用户看，确认后才发出。适合涉及商业机密的研究。
- 用户可以设置站点黑名单（沿用 `aiBlockedSites`）和偏好站点。
- 设置页写清楚：联网搜索会把查询词发给所选的搜索服务；“全本地”模式只用本地模型和自建 SearXNG（或不联网）。

### 4.6 哪些入口可以联网：用途白名单

联网与否由代码决定，不由模型决定。每次 AI 运行都带用途标记（`agent/context.ts` 的 `withRun({ purpose })`）。网关在发出任何搜索或抓取请求前，先按用途查白名单，**不在白名单上的用途一律拒绝**。这样即使以后某个功能误挂了搜索工具，网关也会挡住。

| 策略 | 用途 | 理由 |
|---|---|---|
| **永不联网** | 费曼练习、复盘追问、记忆整理、复习回答检查、录音整理（各视角）、导入生成线索、收件箱归档、今日晨报、计划排期、资料整理（`source_digest`）、外文对照、文档识别、浏览器摘录与网课整理 | 价值在于忠于你自己的材料：费曼练习里 AI 扮演学生，联网等于“自带答案”；录音整理的结论要有原声作证据 |
| **按需联网**（模型判断，用户有开关） | 积微助手：对话页、工作区面板、就地卡片 | 见 §4.7 |
| **流程联网**（代码决定何时搜） | 研究、发现、AI 任务（以任务定义中声明的工具为准）、参谋“补证据”（需同意）、创作工坊“找素材”（用户点了才搜）、笔记核查 | 联网是这些功能本身的一部分 |

白名单写在 `services/retrieval/policy.ts`。新增 AI 功能时，必须在这里登记用途，否则默认不能联网。单元测试会遍历所有已登记的用途，确认每个都有明确策略。

### 4.7 助手的联网判断

**开关三档：关 / 自动（默认）/ 总是。** 每个对话可以单独切换。还没有配置任何可用的搜索后端时，“自动”实际等于“关”，界面明确显示“未联网”。学术接口不算在内：它们只服务学术类查询。

“自动”模式分三步：

1. **先查知识库**：沿用现在每轮生成前的 `retrieve`。在本机完成，不花钱、不外传。
2. **代码算两个信号**，写进本轮消息（`<检索情况>` 块），供模型参考：
   - **知识库覆盖：** 充足 / 部分 / 没有。依据是相似度达到门槛的知识库段落数，见 §4.8 第二步。
   - **时效需求：** 是 / 否。依据是规则：问题里有没有“最新、现在、今年、目前、价格、版本、政策、新闻”这类词或近期日期，用户有没有明说“搜一下 / 查查网上 / 联网”。
3. **模型在这个提示下决定是否调用 `web_search` / `read_url`**，每轮最多 3 次搜索、4 次读取。“总是”模式下，代码保证至少搜一次。

| 情况 | 行为 |
|---|---|
| 选中一段问“解释这段”，或范围限定为指定的笔记 / 资料 | 默认不搜，除非用户明说要查 |
| 知识库充足，且没有时效需求 | 通常不搜 |
| 有时效需求 | 即使知识库有内容也搜，用来核对是否过时 |
| 知识库没有相关内容 | 搜 |
| 没有可用的搜索后端 | 不提供搜索工具；回答注明“未联网”，不得装作查过 |

**不会调用工具的模型**（现有代码遇到会去掉工具重试），以及工具可靠性低的本地模型（`toolReliability`，§8.3），改为**由代码先搜**：信号判断需要联网时，代码用规则改写查询并执行搜索，结果直接放进本轮消息，模型只负责阅读和回答。

工具：

- `web_search(query, type?, freshness?, site?)`：返回编号结果，包括标题、来源、日期和摘要。
- `read_url(url, focus?)`：返回筛选后的段落，每段有编号。

### 4.8 知识库与网页结果的合并

“排序”分成三件事：执行顺序、结果合并、冲突裁决。

**执行顺序：** 永远先查知识库。只有信号明确需要联网时（用户明说，或者有时效需求且处于“总是”模式），才和知识库检索并行，以节省时间。

**结果合并：不能把两边直接混排。** 原因有三：

- `retrieve` 的分数是 RRF 融合后的相对分，只表示先后，不表示有多相关。网页结果的排名来自各家引擎，两种相对排名不可比。
- 单位不同：知识库一条是一个康奈尔行或一个资料片段，网页一条是一整个页面。
- 后果：直接混排时，SEO 网页会挤掉你的笔记，或者反过来。

做法分三步：

**第一步，各自初排。** 知识库沿用 `retrieve`。网页结果先跨后端用 RRF 合并，按规范化 URL 去重，读取排名靠前的页面（快答档最多 3 页），切成段落（复用 `chunks` 的切法）。

**第二步，统一到段落，用同一把尺子打分。** 两边的段落都用 EmbeddingGemma 计算与查询的余弦相似度 `sim`。同一个模型、同样以段落为单位，分数才可比。

```
知识库段落  score = sim × weight(状态, 来源, 最近修改)  × (正在看的资料 ? 1.6 : 1)
网页段落    score = sim × 权威度 × 时效系数
  权威度：官方 / 政府 / 学术 1.2 · 主流媒体 1.0 · 企业自述 0.9 · 个人博客 0.8 · 疑似内容农场 0.5
  时效系数：仅在“时效需求 = 是”时启用，按发布日期衰减（半衰期 90 天，下限 0.5）；否则为 1
```

需要改的现有代码：`retrieve` 要把向量检索得到的相似度随 `SearchHit` 一起返回（目前只有相对分）。只靠关键词命中、没有向量分数的段落，补算一次相似度。

“知识库覆盖”信号也基于 `sim`：达到“相关门槛”（初定 0.55）的段落有 2 条或以上为“充足”，有 1 条为“部分”，没有为“没有”。

**第三步，按名额分配，不排一个大榜。** 本轮可放的段落数 N 由模型的 `contextPractical` 决定，快答档默认 12：

1. 用户正指着的内容（选区、当前资料位置、`contextSourceEvidence`）不参与排序，总是排在最前面，也不占 N。
2. 低于“入选下限”（初定 0.35）的段落，不论来自哪边，一律丢弃。
3. 两边都有合格段落时各自保底 3 个名额。
4. 剩余名额按 `score` 填满。同一网页最多 2 段，同一笔记或资料最多 3 段。
5. 交给模型时分成两块：`<知识库片段>` 和 `<网页资料>`，引用编号连续。

0.55、0.35、各保底 3 个、半衰期 90 天都是初始值，用 `docs/eval/retrieval.md` 的评测，加上新建的中英文混合测试集校准后再确定。

**跨来源去重：** 网页的规范化 URL 和资料库里 `sources.url` 相同时，使用资料库的那份（带用户批注），只算一个来源。内容和收藏时不同的话，提示“网页已更新”。否则同一篇文章会被当成两个独立来源，虚增核验结果。

**冲突裁决：按问题类型定，不按分数。**

| 问题类型 | 以谁为准 |
|---|---|
| 我学过什么 / 我的看法 / 课上或资料里怎么讲 | 知识库；网页只作补充 |
| 事实性、时效性问题（价格、版本、政策、最新研究） | 更新、更权威的网页，并明说“你 2025 年的笔记写的是 X，现在官方是 Y” |
| 两边都不够权威，或判断不了 | 列出两种说法，不替用户选 |

任何情况下都不悄悄覆盖笔记。发现笔记可能过时时，生成“标为存疑 / 已过时”的提案（`notes.status`），由用户决定。这条规则写进系统提示（替换现有规则 2 中“以较新的为准”的笼统说法），并在评测集里设专门的冲突题。

### 4.9 引用、多轮与其他细节

| 问题 | 处理 |
|---|---|
| 引用保存 | 引用新增类型 `web`：指向快照资产和段落里的原文；悬停显示原文，点开在快照阅读器里高亮。`session.hits` 同时收纳网页段落，`citations` 的过滤逻辑不变 |
| 多轮追问时网页内容丢失 | 历史只保存原话。上一轮被引用过的网页段落从快照重新载入本轮（只载入被引用的，不载入全部） |
| 搜索词泄露 | “不给 AI”的内容不进查询，由代码检查；查询限制在 100 字以内；每次搜索都在步骤里显示实际发出的查询；可选“谨慎模式”，发出前先确认 |
| 提示注入 | 网页内容用 `<external-data>` 封装；本轮读过网页之后的写入一律需要确认（现有规则） |
| 花费 | 每轮次数上限、每次运行费用上限（现有）；搜索和抓取单独记账 |
| 网页结果混进知识库 | 搜索缓存和快照不进入 `chunks`。只有用户点“导入资料库”后，才进入检索 |
| 无痕对话 | 可以联网，但不写缓存、不保存快照（引用只保存网址和引语文字） |

## 5. 深度研究引擎

### 5.1 四档投入

| 档位 | 适用 | 做法 | 典型规模 |
|---|---|---|---|
| **快答** | 查一个事实、看个最新消息 | 助手单循环，最多 3 次搜索 | 秒级 |
| **调研** | 需要比较、需要几方说法 | 单智能体 + 计划 + 证据库 + 精简核验 | 10–30 次工具调用，几分钟 |
| **深度研究** | 文献综述、市场分析、重大决策 | 编排者 + 3–6 个并行调查员 + 完整核验 + 分节撰写 + 引用审计 | 15–40 分钟 |
| **持续追踪** | 盯一个方向、竞品、政策 | AI 任务定期运行，只报告与上次相比的增量 | 每天或每周 |

助手发现请求像研究（需要多方来源、要做比较、要写报告），会给出一张卡片：“这个问题适合做调研 / 深度研究，预计用量：中，上限 X（取自你的设置）。开始吗？”。用户也可以直接在「研究」页发起。计划器给出建议档位，用户可以改。

### 5.2 阶段（状态机，每步落库）

```
S0 澄清 ─► S1 计划 ─►（用户审阅）─► S2 先查你自己 ─► S3 并行调查 ─► S4 综合与核验 ─┐
                                                     ▲                          │
                                                     └──── 有缺口且未超预算 ◄─────┘
                                                                                │
                                                     S5 分节撰写 ─► S6 引用审计 ─► S7 交付与回流
```

**S0 澄清。** 最多用 `ask_user` 问 3 个问题，每个问题都给选项，不让用户写作文。问的是：做这个研究是为了什么（要做什么决定 / 写什么 / 学什么）、给谁看、范围（时间、地区、行业）、要多深、有没有必须看或必须避开的来源。能从记忆、方向和知识库推断出来的就不问，直接写进任务书，让用户看一眼。产出是一份**研究任务书**。

**S1 计划。** 计划器（强模型）产出：
- **问题树**：把总问题拆成 3–8 个互不重叠、合起来完整的子问题。决策和市场类问题，同时列出待检验的假设。
- 每个子问题的**检索策略**：类型、语言、时效、建议后端、起始查询（先宽后窄）。
- **预期交付物大纲**（初稿，之后会随证据调整）。
- **投入**：按 R2 的规则决定调查员数量和每人的工具调用预算。

计划默认展示给用户，用户可以增删子问题、改优先级、指定或排除来源，然后点“开始”。也可以在设置里选“默认直接开始”。计划存为 `research_runs.plan`，之后每次重新规划都留一个版本。

**S2 先查你自己。** 对每个子问题检索知识库（`retrieve`）和记忆，得到三类结果：你已经有的材料、你的笔记里已有的看法（注明是你写的还是 AI 写的）、明显的缺口。这些作为调查员任务书的一部分：“用户已经知道 A 和 B，重点查 C；用户笔记里认为 D，请特别寻找支持和反对 D 的证据。”

**S3 并行调查。** 每个子问题交给一个调查员（详见 §5.4）。并发数取决于服务商限速和用户设置，默认 3；本地模型时为 1。调查员把证据写进证据库，只回传不超过 1500 token 的摘要和证据编号。

**S4 综合与核验。** 编排者把证据聚成**论断**，再逐条核验（详见 §5.5）。发现缺口（某个子问题证据不足、出现未调和的冲突、出现新的重要子问题）时，在预算允许的情况下派出补充调查，最多 2 轮。

**S5 分节撰写。** 根据论断重新生成大纲，按节撰写。每节只取该节需要的论断和证据（R5）。详见 §5.6。

**S6 引用审计。** 由另一个模型逐句检查全文。详见 §5.6。

**S7 交付与回流。** 详见 §5.8。

研究运行注册为后台任务 `research.run`，每个阶段完成后写检查点。应用退出或崩溃后，从最近的检查点续跑，已经做过的搜索和读取不重复（有缓存，也有证据库）。

### 5.3 证据库（数据模型）

研究数据存在知识库里（因为它是知识的一部分），新增以下表，都遵守同步约定（UUIDv7、软删除、`updated_by`）：

| 表 | 主要字段 |
|---|---|
| `research_runs` | 标题、任务书、档位、状态（各阶段）、计划（含版本）、模型分工、预算与实际花费、隐私模式、关联的方向 / 决策 / 作品 |
| `research_questions` | 所属运行、父问题、文字、假设、检索策略、状态（待查 / 查询中 / 饱和 / 证据不足） |
| `research_sources` | 规范化 URL 或 DOI、标题、发布方、作者、发布日期、获取日期、快照（素材 sha256）、类型（一手 / 二手 / 评论 / 论文 / 数据 / 你的笔记）、可信度评分与理由、来自哪个后端和哪次查询 |
| `research_evidence` | 来源、原文引语、定位（TextQuote 或页码段落）、转述、所属子问题、立场（支持 / 反对 / 中性）、抽出的数字（值、单位、口径、年份）、抽取模型 |
| `research_claims` | 论断文字、状态（已核实 / 有争议 / 未能确认 / 推断）、置信度（高 / 中 / 低）及理由、支持和反对的证据编号、独立来源数 |
| `research_steps` | 全过程留痕：谁（编排者 / 调查员 n / 审计）、什么工具、参数、结果摘要、花费、时间 |

用户自己的笔记和资料也可以作为证据（类型为“你的笔记”），引用时链接回原段落。

### 5.4 调查员

**任务书**（由编排者生成，格式固定）：目标；为什么查（任务书摘要）；用户已知的内容；要找的东西（可以是需要验证的假设）；检索策略；可用工具；边界（不查什么、到什么程度为止）；预算（工具调用次数）；输出格式。

**工具（少而原子，共 8 个）：**

| 工具 | 作用 |
|---|---|
| `web_search` | 走网关，参数含类型、时效、站点 |
| `scholar_search` | 学术检索，返回标题、作者、年份、期刊、被引数、DOI、是否有开放全文 |
| `paper_links` | 引文滚雪球：某篇论文的参考文献和施引文献 |
| `read_url` | 读取管线，返回筛选段落 |
| `data_fetch` | 从数据连接器取表格 |
| `kb_search` | 查知识库 |
| `record_evidence` | 批量记录证据（引语必须能在已读段落中逐字找到，否则退回给模型修正） |
| `finish` | 提交摘要、证据编号、仍未解决的问题 |

**工作方式：**
- 先用短而宽的查询了解全貌，再收窄（R2）。每拿到一批结果，先做一次简短判断：哪些值得读，还缺什么。
- **饱和即停：** 连续两轮新读的来源没有带来新论断，或者预算用完。
- **引语必须逐字存在：** `record_evidence` 会在已读取的段落里查找引语，找不到就拒收。这样从源头上杜绝编造引文。
- 调查员只读不写，看不到用户的记忆，只能看到任务书里给它的内容。

### 5.5 综合与核验（对付“核验惰性”）

1. **聚类成论断。** 编排者把语义相同的证据归到同一条论断下，并标出相互冲突的论断。
2. **独立来源计数。** 同一出处的转载、同一新闻稿的改写算作一个来源（按规范化 URL、发布方、文本相似度判断）。**关键论断**（大纲里的结论、数字、因果判断）至少需要 2 个独立来源，否则标为“单一来源”。
3. **反向搜索。** 对每条关键论断，专门生成一条找反例的查询（例如“X 的批评”“X 被推翻”“X 数据有误”），由一个轻量调查员执行。这一步针对确认偏误和 R7 中的提前停下。
4. **冲突调和。** 出现冲突时，比较口径（定义、范围、年份、样本）、时间（新的取代旧的）、来源层级（一手数据优先于二手转述）。能调和的写明原因；不能调和的作为“有争议”列出各方说法。**不允许悄悄选一个。**
5. **来源可信度。** 借鉴图书馆界的横向阅读（SIFT）：这个来源是谁、是一手还是二手、有没有利益关系、发布日期、其他来源怎么评价它。打分由规则和模型共同完成：域名类型（政府、学术、主流媒体、企业、个人、内容农场特征）、是否有作者和日期、是否引用了原始数据。用户可以把站点标为“可信”或“不要用”，这个设置会被记住。
6. **数字检查。** 所有数字带单位、口径和年份。凡是由其他数字推算出来的（增长率、份额、换算），都在分析工作台里实际计算，不让模型心算（§6）。
7. **置信度。** 由规则给出：独立来源数、来源可信度、是否有未调和的冲突、证据的时效。模型可以在规则的结果上下调，不能上调。

### 5.6 分节撰写与引用审计

**撰写：**
- 大纲由论断生成，而不是先有大纲再找证据（R5）。每节写作时只拿本节的论断、证据引语和来源信息。
- 每个事实句都带证据编号，渲染成 `[n]`。没有证据的句子只允许三种：过渡句、明确标出的推断（“据此推断……”）、标出的通用知识。
- 报告固定包含这几部分：**结论摘要**（每条带置信度）→ 正文各节 → **和你已有知识的关系**（印证 / 补充 / 冲突，并链接到具体笔记）→ **有争议和未能确认的地方** → **局限**（没查到的、时间范围、语言范围）→ **方法**（问题树、检索了哪些库、用了哪些查询、日期、读了多少来源）→ 来源列表。
- 篇幅和风格按任务书里的用途和读者调整：给自己看的学习型、给领导看的简报型、学术综述型。

**引用审计（独立的一步，换一个模型）：**
- 把报告拆成句子。对每个事实句，取出它引用的证据原文，用“蕴含判断”提示让审计模型判断：支持 / 部分支持 / 不支持 / 没有引用但需要引用。
- 审计模型尽量和撰写模型来自不同厂商或不同系列（减少自我偏好）；没有条件时用同一模型的新上下文。
- 不支持的句子退回撰写者修改，或者降级为“推断”，或者删除。改完再审一次，最多两轮。
- 结果写在报告顶部：“核验：38 条结论，34 条有两个以上独立来源，3 条有争议，1 条未能确认；引用支持率 97%”。

### 5.7 上下文工程

- **编排者：** 系统提示固定（规则 + 技能目录 + 用户卡片），可以命中前缀缓存。每一步把当前计划和待办以简短形式重写在消息末尾（R18）。看不到原始网页，只看到调查员摘要和论断表。
- **调查员：** 每个都从干净的上下文开始，只拿任务书。原始页面不留在上下文里；读过的段落用编号代替，需要时通过证据库查回。
- **长工具输出：** 存进研究工作区（数据库和素材仓库），模型只拿到编号和摘要。
- **不同档位的上下文预算：** 根据模型的实际可用上下文（来自模型能力档案，§8.3）决定每次给多少段落、保留多少步历史。

### 5.8 交付与回流

报告完成后，在报告页上提供这些操作（都走提案或确认）：

- **存为笔记：** 新增笔记类型 `research`（结构：摘要 / 正文 / 方法 / 来源；结论行可以转为康奈尔线索，从而生成复习卡片）。引用都保留为可点击的出处链接。
- **导入来源：** 勾选来源导入资料库，快照成为正式资料，进入检索和批注。
- **笔记状态建议：** “和你已有知识的关系”中被推翻的笔记，生成“标为存疑 / 已过时 / 被取代”的提案（`notes.status`、`superseded_by` 已有）。
- **洞见与行动：** 结论成为洞见候选，未解决的问题成为行动项，都需用户确认。
- **继续加工：** 一键送进创作工坊（长文 / 课件 / 讲解视频）、做成播客、交给参谋做决策。
- **持续追踪：** 生成一个 AI 任务，每周用同一份计划只搜新内容，只报告变化。
- **导出：** Word、PDF、Markdown；证据表导出为 CSV；学术来源导出为 BibTeX / RIS。
- **重跑与对比：** 隔一段时间用同一计划重跑，对比结论的变化。

### 5.9 运行中的交互

「研究」页布局：左边是问题树（每个子问题的状态和证据数），中间是实时更新的报告草稿或进展摘要，右边是来源和证据面板，顶部是阶段进度、已用花费和预算、暂停 / 停止按钮。

- **插话调整：** 运行中可以输入“再看看日本市场”“别用某某网站”“这个子问题不重要”。这些话在下一个步骤边界注入编排者的消息，并记入计划版本。这个简单的异步方式解决了 R3 中提到的“同步等待、无法中途调整”的问题。
- **审阅证据：** 可以把某条证据或某个来源标为“不可信”，编排者会重新评估受影响的论断。
- **通知：** 研究完成时，如果窗口不在前台，发系统通知（沿用 `notifyDone`）。

## 6. 分析工作台

### 6.1 运行环境：两级

| | Pyodide（默认） | 本机 Python（可选插件） |
|---|---|---|
| 是什么 | WebAssembly 版 CPython，在隔离的工作进程里运行 | micromamba 按锁文件离线安装的 conda 环境（复用 Manim 的安装、校验和签名管线） |
| 隔离 | WebAssembly 沙箱，天然没有网络和文件系统访问；只能通过受控接口读写工作区 | macOS 用 `sandbox-exec`（禁网，只能写工作目录）；Linux 用 bubblewrap；Windows 每次运行都需确认，并限制时间和内存（如实告诉用户 Windows 上隔离较弱） |
| 体积 | 按需下载并缓存，几十 MB 级 | 数百 MB 级，用户主动安装，可以删除 |
| 能力 | pandas、numpy、scipy、statsmodels、scikit-learn、matplotlib；DuckDB（WASM） | 完整生态，适合大数据集和长时间计算 |
| 限制 | 内存上限约 2–4 GB，速度较慢 | 需要磁盘空间 |

一次分析会话对应一个有状态的内核：变量在多次执行之间保留，文件在会话工作区里。每次执行限制时间（默认 60 秒，可延长）和输出大小。

### 6.2 工具

| 工具 | 作用 |
|---|---|
| `data_load` | 把资料库里的 CSV / XLSX、笔记里的表格、研究证据中的数字、数据连接器的表格载入工作区 |
| `data_profile` | **强制第一步**：行列数、类型、缺失值、唯一值、分布、异常值、疑似单位和口径问题 |
| `py_run` | 执行代码，返回标准输出、表格（截断后的预览）、图片和错误 |
| `chart` | 优先输出 Vega-Lite 规格，由积微按主题渲染（深色模式和配色一致）；复杂图用 matplotlib 出图 |
| `assert_check` | 对账检查：行数、总和、比例加起来是否为 100%、关联前后行数变化 |

### 6.3 分析流程（以技能形式交付，弱模型由代码强制执行）

1. **读懂问题和数据：** 复述分析目标、关键指标的定义和约束；不清楚就问。
2. **数据画像：** 必须先调用 `data_profile`，没有画像不能开始分析（直接针对 R10 的“没把数据看全”）。
3. **分析计划：** 列出要做的分析、用什么方法、为什么。
4. **执行：** 每步都附带断言；关联、筛选、聚合之后检查行数和总量。
5. **复核：** 关键数字用另一种写法重新算一遍（强模型档位下由审计模型独立写代码复算），两次不一致就报警。
6. **解读：** 必须写清样本量、效应大小、显著性或不确定性；相关不等于因果；指出可能的混杂因素和数据局限。
7. **可复现：** 导出 `.ipynb` 或 `.py`；报告里的每个数字都链接到产生它的代码单元。

### 6.4 和研究、笔记的结合

- 研究里需要推算的数字（增长率、市场规模的自下而上估算、敏感性分析）都在工作台里计算，计算记录成为证据的一部分。
- 分析结果可以作为图表块插入笔记（富内容块框架已有），数据和代码一起存储，以后可以重新运行。
- 市场规模这类估算，假设做成可调参数表，像参谋的决策矩阵一样拖动参数就能看到结果变化。

## 7. 三类人群的工作流

工作流以技能加模板的形式交付，内置在角色包里（大学生·科研、产品经理、管理者等已有角色包会相应更新）。

### 7.1 研究者：文献综述与科研

- **透明检索：** 记录检索式、数据库、日期和筛选条件（PRISMA 精简版）。积微建议检索式，用户确认后执行；结果和数量都留档，以后可以复现（R14）。
- **筛选表：** 标题和摘要逐篇给出“纳入 / 排除 / 待定”建议和理由。用户做最终决定，AI 是第二审阅人。
- **抽取表：** 用户定义字段（研究对象、方法、样本量、主要结果、局限），AI 逐篇抽取，每格都附带原文引语。引语找不到的格子标红。
- **引文滚雪球：** 从种子论文向前、向后追踪参考文献和施引文献，按相关度排序。
- **证据分级：** 借鉴 GRADE 的思路，按研究设计、样本量、一致性、直接性给出高 / 中 / 低 / 极低。
- **研究空白：** 汇总后列出没有被研究过、或者结论冲突的方向，连到用户的方向和笔记。
- **出口：** BibTeX / RIS 导出；开放获取的全文通过 Unpaywall 找到后可以导入资料库精读（精读、批注、出卡片都已有）。

### 7.2 市场分析与数据分析

- **市场规模：** 自上而下和自下而上两种方法都做，相互印证；TAM / SAM / SOM 的每个假设都列出来源，或者明确标为假设；附敏感性分析。
- **竞品矩阵：** 维度由用户确认，每个格子都有来源和日期；过时的信息（超过设定期限）标黄。
- **需求证据：** 区分用户原话（评论、论坛、调研）和机构判断。
- **环境分析：** PEST、波特五力作为可选框架，不硬套。
- **数字纪律：** 每个数字都写明来源、年份和口径；不同口径的数字不能直接比较，要并排列出。
- **持续追踪：** 竞品和政策设为每周追踪，只报告变化。

### 7.3 决策者：和参谋融合

参谋现在只在知识库里找依据。融合之后：

- 参谋发现依据不足时，提出“联网补证据”，在用户同意后以调研档执行，证据进入备忘录。
- **外部视角：** 先找参照类别和基准率（类似的事通常怎样），再看这件事的特殊之处。
- **概率估计：** 需要预测时，生成 3 份相互独立的估计（不同提示和视角，条件允许时用不同模型），再调和，并给出理由（R19）。决策日志在回看日期对照实际结果，持续统计用户和积微的校准情况。
- 事前验尸、反方意见里的每一条风险，都尽量附上真实案例作为证据。

### 7.4 学习者

- **笔记核查：** 对一篇笔记逐条核对事实，给出“印证 / 有新说法 / 可能有误”，附来源；结果以提案形式标注，用户决定是否修改或把笔记标为存疑。这也是积微“知识会迭代”理念的直接体现。
- **专题入门：** 为一个新方向研究出学习路径：核心概念、权威入门资料、常见误解，结果进入「发现」和「计划」。
- **讲解时引用权威来源：** 解释概念时可以联网找教科书、百科或课程讲义作为出处。

## 8. 本地大模型与模型路由

### 8.1 运行时

- 扩展现有的 llama-server 附属进程：从只跑 EmbeddingGemma，扩展为同时托管**对话模型**、**向量模型**和可选的**重排模型**。优先使用路由模式（一个端点、按需加载、LRU 换出、每个模型独立进程，R20）；如果捆绑的版本不支持路由模式，就由积微自己管理多个进程。具体以选定版本的 `llama-server --help` 为准，P0 先做技术验证。
- 下载复用现有的多镜像测速、慢速切换、断点续传和 sha256 校验。模型目录放在可远程更新的清单里（与官方插件市场一样：线上优先、内置兜底），因为本地模型几乎每月都有新版本。
- 对话请求走 OpenAI 兼容接口，`model.ts` 里新增服务商类型 `local`，和云端走同一套代码。Ollama 预设保留，作为“已有 Ollama 的用户”的选项。

### 8.2 硬件检测与推荐

安装时读取内存、显存和芯片类型（Apple 芯片的统一内存按约 70% 可用计算），给出推荐。下表只是初始方向，正式列表在实施时实测后写入目录：

| 可用内存 | 推荐方向 | 定位 |
|---|---|---|
| 8 GB | Qwen3.5-4B（Q4） | 本地基础：摘要、分类、抽取、查询改写、段落筛选、引用审计初筛 |
| 16 GB | Qwen3.5-9B（Q5），或 Gemma 4 26B-A4B（低位量化） | 本地普通：调研档的调查员、混合模式下读私密内容 |
| 32 GB 及以上 | Qwen3.6-35B-A3B、Qwen3.8-27B、Gemma 4 31B、GLM-4.7-Flash；研究专用候选：通义 DeepResearch-30B-A3B | 本地强：可以独立完成调研档，深度研究档仍建议云端写作 |

每个模型在目录里写明许可证（Apache-2.0、Gemma 条款等），积微只下载许可允许个人使用的模型。

### 8.3 模型能力档案

现有的 `resolveCaps` 只有 `tier`（strong / basic）和 `vision`。扩展为：

```ts
interface ModelCaps {
  tier: 'strong' | 'basic' | 'local-strong' | 'local-basic'
  vision: boolean
  contextPractical: number      // 实际可用的上下文（受量化和内存影响）
  parallelTools: boolean        // 一步内能否发出多个工具调用
  toolReliability: number       // 0–1，由自测得出（本地模型）或按名称表给出（云端）
  structured: 'json-schema' | 'tool' | 'text'  // 结构化输出的可靠方式
  family: string                // 用来让审计模型避开撰写模型的系列
}
```

**本地模型自测：** 安装后运行 12 个固定的多轮工具任务（搜索→读取→记录证据→结束；含一次故意报错，看能否恢复；含重复调用陷阱），统计成功率、循环率和格式错误率，写入 `toolReliability`。R15 说明单次调用的准确率会严重高估多轮能力，所以自测必须是多轮的。

### 8.4 按角色分工的模型路由

研究引擎里的每个角色单独选模型，默认“自动”：

| 角色 | 需要什么 | 自动选择 |
|---|---|---|
| 计划 / 编排 | 推理、拆解 | 当前对话模型（强模型最佳） |
| 调查员 | 工具调用稳定、便宜、快 | 同服务商的快速模型（例如 deepseek-flash），或本地普通以上 |
| 抽取 / 段落筛选 / 去重 | 便宜、大量 | 本地基础模型（有的话），否则快速模型 |
| 核验 / 引用审计 | 判断准确、和撰写者不同系列 | 另一个已配置的服务商；否则同一模型开新上下文 |
| 撰写 | 文笔、长输出 | 当前对话模型 |

设置里有“研究模型分工”，高级用户可以手动指定。所有选择都记入 `research_runs`，方便复现和对比。

**三种隐私模式：**

| 模式 | 私密内容（笔记、资料、记忆）谁来读 | 公开网页谁来读 | 云端看到什么 |
|---|---|---|---|
| 云端 | 云端模型 | 云端模型 | 全部（现有行为，仍遵守“不给 AI”） |
| **混合** | 只有本地模型 | 云端或本地 | 本地模型整理出的摘要和问题（R17），用户可以预览 |
| 全本地 | 本地模型 | 本地模型 | 什么也看不到；搜索只用自建 SearXNG 或学术接口，或完全不联网 |

### 8.5 让弱模型和本地模型也能把事做对

- **代码编排，模型填空：** `tier` 为 basic 或 local 时，阶段的推进、循环、停止条件都由代码控制。模型每次只做一件小事：生成 3 条查询、从这 8 段里选证据、判断这句是否被支持。强模型时由编排者自己决定下一步。
- **每个阶段只给相关的工具：** 调查阶段只有 4–5 个工具，减少工具名幻觉。
- **结构化输出受约束：** 本地模型用 llama-server 的 JSON Schema 约束输出；云端优先“强制调用提交工具”（`ai/structured.ts` 已有）。
- **循环检测：** 同一工具、同样参数连续出现 2 次就拦下，并把提示返回给模型；连续 3 次格式错误就换成更小的子任务，或者换成更强的模型（征得同意）。
- **短上下文：** 段落筛选、证据编号化，让 8K 上下文的本地模型也能工作。
- **诚实降级：** 弱模型跑深度研究时，核验步骤不能省。时间或能力不够时，报告直接写出“哪些结论未经核验”，不输出看似完整的报告。

## 9. 质量评测

**内置评测集**（`e2e/eval/research/`，`JIWEI_EVAL=1` 时运行，不进默认 CI；按测试偏好，只在相关改动时运行）：

- 30 个真实任务：研究者 10 个、市场与数据 10 个、决策与学习 10 个，中英文各半。每个任务有评分要点（必须覆盖的点、不能出现的错误）。
- **噪声测试**（DRNOISE 式）：用现有的 `JIWEI_SEARCH_BASE` 本地模拟搜索服务，在结果里放一篇似是而非的文档，检查积微能否发现冲突并调和，而不是直接采信。
- **数据分析题**：带隐藏陷阱的数据集（重复行、单位混用、缺失值编码成 0），检查数据画像和断言能否发现问题。

**指标：**

| 指标 | 怎么算 |
|---|---|
| 引用支持率 | FACT 式：抽出“句子—证据”对，判断是否支持 |
| 未引用事实句比例 | DEER 式：需要引用却没有引用的句子占比 |
| 要点覆盖率 | 对照评分要点 |
| 来源质量 | 一手 / 权威来源占比、内容农场出现次数 |
| 噪声抵抗 | 噪声条件和干净条件下的准确率差 |
| 花费与耗时 | 每个任务的 token、搜索次数、时间 |

评审模型按 Anthropic 的五项打分（事实准确、引用准确、完整性、来源质量、工具效率），每个维度 0–1 分，再给出通过或不通过。每次改动提示词或流程后，和上一次的结果对比。

**产品内的质量信号：** 用户可以在任意引用上点“这条引用不对”，或把来源标为不可信。这些反馈进入来源可信度，以及技能偏好学习（现有机制）。

## 10. 安全、隐私与费用

| 风险 | 对策 |
|---|---|
| 网页里的提示注入 | `<external-data>` 封装；调查员没有写入工具；可疑指令文字被标记；读过外部内容之后的写入一律需要确认（现有规则） |
| 查询泄露私密信息 | “不给 AI”内容不进查询并有检查；谨慎模式下外发前预览；混合 / 全本地模式 |
| 抓取越界 | 每个域名排队限速（现有，间隔 2 秒）；不绕过人机验证、付费墙和登录；只在用户同意后读取已登录的标签页 |
| 版权 | 快照只保存在本机供个人研究使用；报告引用短摘录；导出时附链接，不附全文 |
| 代码执行 | Pyodide 天然隔离；本机 Python 有沙箱、禁网、时间和内存限制；Windows 每次确认 |
| 失控花费 | 档位、运行前预估、每次运行上限（现有 `perRunLimit`）、实时显示、随时暂停；搜索和抓取单独记账 |
| 幻觉与伪造引文 | 引语逐字校验；独立来源计数；反向搜索；全文引用审计；置信度由规则给出 |

## 13. 需要你决定的问题

1. **默认搜索后端。** 建议：零配置时开启学术接口（免费），并在引导里推荐配置一个中文通用搜索（博查或智谱）和一个英文通用搜索（Tavily 或 Brave）。积微不提供共用 Key（成本和滥用都无法控制）。
2. **「研究」放在哪里。** 是新开一个一级导航，还是放进「创作」组？建议单独做一级导航：研究是积微的核心价值，应该一眼就能看到。
3. **Windows 上的本机 Python。** 建议 Windows 默认只用 Pyodide；本机 Python 插件在 Windows 上每次运行都要确认，并明确告诉用户隔离较弱。
4. **研究报告的形态。** 建议新增笔记类型 `research`，而不是复用 `reading`，这样方法、来源、核验信息都有固定的位置。
5. **本地模型的磁盘占用。** 32 GB 机器推荐的模型约 20 GB。是否接受“推荐但不默认下载”，由用户在设置里主动安装？
6. **版本顺序。** 本设计把本地大模型放在 v0.16，前面的版本只预留抽象层。如果你希望更早支持本地模型，可以和 v0.15 对调。
