# 知识图谱改版设计（v0.14.2 – v0.14.3）

> 起因：用户反馈知识图谱“太简陋、太丑，影响整个产品品质”，并提出“逻辑关系要不要体现、怎么体现”。
> 本文先回答“为什么要体现逻辑”，再给出数据、生成、呈现、交互四部分方案，最后列出参考的优秀产品和分期。

## 1. 现状与问题

用 42 篇笔记（5 个分类）、4 份资料、56 条连线实测截图，问题有三层：

**看不清（视觉）**
- 分类色取自粉彩的“墨色”，经济学、统计学、编程都是相近的深蓝灰；深色模式下都是相近的浅蓝。
- 所有节点一样大，枢纽笔记（A/B 测试、间隔重复）和边缘笔记看不出差别。
- 同一分类的笔记在画面里混在一起，没有“区域”的感觉。
- 连线全是同一种绿色细线；文字没有底，被连线穿过。

**看不懂（语义）**
- 连线只有“有关”这一种意思。图告诉你 A 和 B 有关，却不告诉你**怎么有关**：A 是 B 的前提？A 推出了 B？A 和 B 容易混？B 是 A 的例子？
- 数据库里其实早有 `links.relation` 字段（reference、related、supersedes、evidence、derived_from、contradicts、applied_in），但从没被写入，也没被画出来。

**用不上（价值）**
- 图只能看，不能回答学习者真正关心的问题：我下一步该学什么？哪里没学扎实会拖累后面？哪些知识彼此孤立、还没融会贯通？哪些笔记已经过时或互相矛盾？

## 2. 结论：要体现逻辑关系，但要“少而准、可解释、能用上”

一张只有“有关”的网，节点一多就是一团毛线，好看与否都难以带来价值。逻辑关系是图谱从“装饰”变成“工具”的关键：

1. **前置关系**让图能排出学习顺序，结合掌握度就能告诉你“现在可以学什么”（参考 Math Academy、Khan Academy 的知识地图）。
2. **推理与例证关系**让一篇笔记的来龙去脉可以顺着读下来，这正是费曼学习法和复盘需要的。
3. **对比、矛盾、过时**让易混点和需要更新的知识浮出来，直接接到复习和 v0.13 的联网核对。

同时要避免三个坑：
- **类型太多**：关系词表控制在 8 个以内，画面上只分 4 个“家族”（相关、结构与顺序、推理、张力），否则用户既不会标、也看不懂。
- **AI 乱连**：AI 推断的关系一律先作为“建议”显示（虚化 + 标签），必须带一句理由和出处句子，用户确认后才算数。不改用户的笔记正文。
- **全图过载**：全景里只淡淡地画出结构，逻辑细节在“局部”和“学习路径”视图里展开，并配文字列表，不靠看图猜。

## 3. 关系词表

| 关系 | 方向 | 读法（局部视图里的句子） | 家族 | 现有字段 |
|---|---|---|---|---|
| 相关 | 无 | A 与 B 相关 | 关联 | reference / related（已有） |
| 前置 | A → B | 学 B 之前要先懂 A | 顺序 | 新增 `prerequisite` |
| 属于 | A → B | A 是 B 的一部分 / 一种 | 结构 | 新增 `part_of` |
| 推出 | A → B | 由 A 推出 / 导致 B | 推理 | 沿用 `derived_from`（方向反过来存） |
| 例证 | A → B | A 是 B 的例子或证据 | 推理 | 沿用 `evidence` |
| 应用 | A → B | B 是 A 的应用 | 推理 | 沿用 `applied_in` |
| 对比 | 无 | A 与 B 容易混 / 要对照着看 | 张力 | 新增 `contrasts` |
| 矛盾 | 无 | A 与 B 的说法冲突 | 张力 | 沿用 `contradicts` |
| 取代 | A → B | A 已被 B 更新 | 张力 | 沿用 `supersedes` |

四个家族在画面上的编码（色弱时仍可分辨，不只靠颜色）：
- **关联**：细、淡、无箭头。
- **顺序**：带箭头的实线，黛蓝。
- **推理**：带箭头的实线，青碧；例证 / 应用线稍细。
- **张力**：赭橙；对比无箭头，矛盾加粗，取代带箭头且终点笔记标“已更新”。
- **AI 建议**：同家族样式但半透明，悬停显示“建议 · 理由”，点一下确认或否决。

## 4. 关系从哪里来

**4.1 用户直接标（零成本，第一期就做）**
- 笔记的“关联”面板：建立关联时可以选关系类型（默认“相关”），已有的关联可以改类型、改方向。
- 图上：从一个节点拖到另一个节点即建立关联并选类型；点连线可以改类型或删除。
- 正文链接保持“相关”，可以在关联面板里升级为具体类型（不改正文）。

**4.2 AI 整理关系（按需触发，第二期）**
- 入口：图谱右上角“整理关系”，或单篇笔记的“理清这篇的来龙去脉”。
- 对每条未定类型的连线，把**连线所在的那句话**（`from_block_id` 对应段落）、两篇笔记的标题和线索栏交给模型，输出：类型、方向、一句理由、引用的原句、置信度。低于阈值的不出建议。
- 发现缺失的关系：用已有的向量相似（相关推荐）找“相似但没连”的笔记对，再让模型判断是否构成前置 / 对比 / 推理；只给建议。
- 成本可控：只处理新增或变更的连线（记录已判断过的），批量请求；设置里可关闭；本地模型也可用；不发送“不给 AI”的笔记。
- 结果进入“关系建议”清单：可逐条或批量确认、否决（否决后不再提）。

**4.3 数据**
- `links` 新增 `status`（confirmed / suggested / rejected）、`reason`、`quote`、`confidence`；`origin` 增加 `ai`；`relation` 枚举增加 prerequisite、part_of、contrasts。
- `KnowledgeGraph.edges` 增加 `relation`、`directed`、`status`、`reason`；节点增加 `degree`（连接数）、`summary`（总结栏首句，用于悬停卡片）、`updatedAt`。
- 迁移用 drizzle-kit 生成；旧数据全部视为 confirmed 的“相关”，行为不变。

## 5. 呈现：三种视图

**5.1 全景（默认）**
- 分类用 v0.14 的分类色（--viz-1…8，按分类顺序固定分配，深浅主题各一套）；无分类为灰色；资料为空心圆环。
- 节点大小 = 连接数为主、字数为辅；最大的一批始终显示标题，其余随缩放出现；标题带底色描边，不被线穿过。
- 布局：力导向加“同分类聚拢”的引力；每个分类画一块柔和的底色区域并标名字（凸包或圆角块，画在 WebGL 层下面的 2D 画布上，随镜头移动）。没有任何连接的笔记集中到右下“未关联”一角。
- 连线按家族编码（第 3 节）；全景下关联线更淡，突出有逻辑类型的线。
- 悬停：本节点和邻居高亮，其余淡出；出现悬停卡片：标题、分类、掌握度、总结栏首句、连接数。
- 枢纽标记：中介中心度最高的几篇（连接不同分类的“桥”）加一圈细光环，图例里解释“枢纽笔记”。

**5.2 局部（点一篇笔记进入）**
- 以这篇为中心的径向布局，1–2 步可调；按关系分扇区：上方是它的前置，下方是由它推出 / 应用，两侧是对比与例证。
- 右侧面板用句子列出这篇的全部关系（“学它之前要先懂：边际效用、机会成本”“由它推出：市场均衡”），每句可点、可改、可确认建议。这是“逻辑能看懂”的关键：图给直觉，句子给准确。

**5.3 学习路径（只看前置关系）**
- 从左到右分层排列（先修在左），节点按掌握度着色。
- 自动标出“可以学了”：前置都已掌握、自己还没掌握的笔记（学习前沿），以及“卡点”：没掌握却挡住很多后续的笔记。
- 点节点：开始复习、打开笔记，或让积微助手为它出题。
- 前置关系中出现环时提示用户检查（通常是标反了）。

## 6. 其它补齐品质的点

| 方面 | 做法 | 参考 |
|---|---|---|
| 操作 | 右下角缩放 +/−、适应画面、回到中心；键盘：/ 搜索、Esc 取消、方向键在邻居间移动 | Obsidian、Kumu |
| 筛选 | 图例可点：按分类、关系家族、掌握度、是否含资料筛选；局部深度滑块 | Obsidian 的分组与局部图、Kumu |
| 知识缺口 | “发现”面板列出：孤立笔记、只靠一条线连着的分类、两个分类之间缺桥；附 AI 建议的连接问题（“p 值和需求曲线之间有什么关系？”）可一键发给助手 | InfraNodus 的结构缺口 |
| 过时与矛盾 | 有“矛盾”“取代”关系或状态为过时的笔记加标记，接到 v0.13 的联网核对 | — |
| 时间 | 时间轴滑块回放知识网的生长（按笔记创建时间），也可只看最近一个月新增 | Obsidian 的时间回放插件 |
| 资料视角 | 选中一份资料时，显示由它衍生的笔记和这些笔记之间的关系 | Connected Papers |
| 列表视图 | 同一份数据的表格：每行一条关系（A — 关系 — B — 理由 — 状态），可排序、批量确认；方便精读，也照顾读屏 | Kumu、Neo4j Bloom |
| 助手 | 可以对积微说“把和 p 值有前置关系的笔记排个学习顺序”，回答里用组件显示（后续可新增 graph 组件） | Neo4j Bloom 的自然语言探索 |
| 动效与性能 | 入场时节点从分类中心散开（300ms），布局稳定后停止；1000 个节点保持流畅（WebGL + 只在需要时重绘） | — |
| 空状态 | 没有连线时说明怎么建立关联，并提供“让积微帮我找关系” | — |

## 7. 参考的产品与取舍

- **Obsidian 图谱**：局部图、深度、分组着色、力参数可调、时间回放。取其局部图与分组；不暴露力参数这类调参项。
- **Heptabase / Scrintal**：卡片式白板，关系有标签，靠空间位置表达结构。取悬停卡片与关系标签；不做自由白板（v0.9 已有画布式工具，后续可从图谱“拖到白板”）。
- **InfraNodus**：主题聚类、中介中心度、结构缺口与“桥接问题”。取枢纽与缺口分析，这是对学习者最有用的洞察。
- **Kumu**：关系类型的样式系统、图例即筛选、聚焦模式。取其样式编码与可点图例。
- **Math Academy / Khan Academy 知识地图**：前置关系 + 掌握度 = 学习前沿。取“学习路径”视图。
- **Connected Papers**：以一份文献为中心看衍生关系。取资料视角。
- **Neo4j Bloom**：搜索驱动、按需展开、自然语言提问。取“从助手提问到图上展开”的方向。
