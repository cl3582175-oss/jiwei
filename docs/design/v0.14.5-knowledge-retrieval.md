# 知识检索与问答升级设计（v0.14.5 – v0.14.7）

> 起因（2026-10-14）：用户感觉积微的 RAG 不足，先请 Codex 做了分析，要求 Claude 不默认它正确，自己核查、双向补充，设计一个用户用着方便、能真正解决问题的 RAG；Codex 按说明书实施，Claude 审查、修正、发版。用户提供了一批真实资料作测试素材（技术协议与招标文件、创业课程资料包与合同模板、古籍扫描本、英文论文、课程视频、图片）。
>
> 第二轮（同日）用户指出：第一版只考虑了“资料里的文字能不能被找到”，覆盖的使用场景太少；目标是**能解决问题的智能**，原有基线（架构、参数、做法）如果妨碍这个目标，就升级它，不能让它成为桎梏。本稿据此重写。
>
> 版本：分三版做完，都放在深度研究（v0.15）之前，因为深度研究的“证据库与核验”就建在这套检索之上。v0.14.5 与正在实施的 v0.14.4（对话附件）并行，见 §10。

## 1. 结论

积微的知识检索现在是一个**“取 8 段文字交给模型”的单次管道**：只搜笔记和资料两类数据，只认文字片段这一种粒度，不管问题是查一个参数、比较两个方案、汇总一学期的内容，还是找视频里老师讲某句话的位置，都走同一条路。资料本身还常被读坏、切碎。

升级目标：**把它变成一个“会按问题选办法”的检索智能体，建在一个读得懂、切得对、什么数据都能搜的知识底座上。**

| 层 | 现在 | 升级后 |
|---|---|---|
| 资料底座 | Word 表格切成碎片；PDF 假汉字；`.doc` 读不了；页眉混入；扫描件状态不透明 | 按结构解析、带章节路径；规范化；`.doc`；就绪状态与一键补救；旧资料自动升级 |
| 能搜到的数据 | 笔记、资料、批注、笔记图片文字 | 再加：错题、收件箱、邮件、洞见、决策日志、存下的回答、（可选）过去的对话 |
| 检索单位 | 文字片段 | 片段 + 章节 + **资料卡**（每份资料的摘要、关键词、类型、时间、人物） |
| 召回 | 三字关键词 + 向量 | 中文分词关键词 + 子串 + 精确编号 + 向量 + 资料卡 / 资料名 + 时间、类型、人物筛选 |
| 排序 | 倒数排名融合 + 时间加权 | 融合后用重排序模型精排（以评测为准） |
| 回答方式 | 固定 8 段 | 按问题类型选策略：查找、整篇读、逐个比较、列举汇总、逐份抽取成表、读章节摘要、媒体定位 |
| 证据量 | 固定 8 段 | 按模型上下文和问题类型调整；小资料整篇给模型 |
| 结果 | 回答 + 引用 | 回答 + 引用（带章节、页码、时间点）+ 没读到什么 + 一键补救 |
| 评测 | 14 篇笔记、40 题 | 真实资料 + 合成个人数据，按场景分组，检索层和回答层都测 |

## 2. 用户场景：积微要解决的问题

积微的用户是八种角色包对应的人（中学生、大学生·科研、考研、求职者、产品经理、教师、内容创作者、管理者）。他们放进积微的东西有：笔记、PDF / Word / 电子书、网页、网课视频、课堂和会议录音、手机照片和截图、邮件、收件箱随手记、错题。检索不只服务于对话，也被参谋、学习路径、费曼练习、创作工坊、MCP 服务（给 Claude Code 等外部 AI 用）、收件箱整理、语音视角、浏览器相关笔记、每日精选使用。

把这些人会问的问题按“需要系统怎么找”分类，每类对照现状：

| # | 场景（例子） | 需要什么 | 现状 |
|---|---|---|---|
| S1 | **查一个事实 / 参数 / 定义**：“多路阀总装线的节拍要求是多少”“p 值是什么” | 精准定位一段原文 | 文字型资料尚可；Word 表格、编号条款、两字词、PDF 假汉字基本失败 |
| S2 | **在指定的一份资料里问**：“这份合同里违约责任怎么写的”“这本书第三章讲什么” | 只在这份里找；小资料最好整篇读 | 先全库取 24 条再过滤，目标资料常被挤掉；小资料也只给 8 段 |
| S3 | **按名字提到资料**：“614 所那份协议的验收标准” | 认出是哪份资料 | 不认资料名，十几份相似协议互相干扰 |
| S4 | **比较**：“方案 A 和 B 有什么区别”“老师讲的和书上有什么不同” | 每个对象分别找证据 | 一次检索，常常只找到一边 |
| S5 | **列举 / 汇总**：“我有哪些讲融资的资料”“这学期我记了哪些关于极限的内容”“这些协议里节拍要求最严的是哪个” | 先列出全部相关对象，再逐个看 | 前 8 段代表不了“全部”，会漏、会把没找到说成没有 |
| S6 | **整理成表**：“把这 12 份协议的工期、付款方式、质保期列成表”“这 20 篇论文的方法和数据集对比” | 逐份抽取、按同一口径汇总 | 没有这个能力 |
| S7 | **总结 / 理解整本书或长资料**：“用一页纸讲清这本书”“资治通鉴第十册的主线” | 章节级概要，分批读完 | 有后台整理（`source_digest`），但结果不能复用于后续问答 |
| S8 | **媒体里定位**：“视频里哪里讲到股权代持”“会议上谁说了要延期” | 转写稿检索、时间点、说话人 | 有转写和说话人；检索不按时间点组织，问题里的人名、时间不会自动变成筛选 |
| S9 | **按时间 / 来源找**：“上周会议决定了什么”“上个月读的那篇讲注意力的论文” | 理解“上周”“论文”“会议”并筛选 | 只有工具里能筛选，一般问题不会自动筛 |
| S10 | **找自己记过的东西**：“我在哪记过这个”“我之前错过类似的题吗”“上次你怎么跟我解释的” | 搜笔记、收件箱、错题、邮件、过去的对话 | 错题、收件箱、邮件、洞见、决策、对话都不在统一检索里 |
| S11 | **跨语言**：用中文问英文论文、用英文问中文资料 | 语义检索跨语言；关键词也能跨 | 向量尚可（实测见 §3），关键词通道完全失效 |
| S12 | **图片 / 扫描 / 手写**：“那张有流程图的白板照片”“扫描版合同里的付款条款” | 识别文字 + 图像描述；扫描件状态透明 | 能识别，但没识别时用户不知道；照片没有描述就搜不到 |
| S13 | **学习用途**：出练习卷、费曼追问、复习卡、讲解视频 | 某主题的**全面、不重复**的素材，而不是最像的 8 段 | 相似片段扎堆，覆盖面不够 |
| S14 | **知识不在库里 / 已过时 / 有冲突** | 如实说没有、区分新旧、提示冲突、需要时联网 | 有状态加权和联网判断；“库里没找到”与“库里没有”不分 |
| S15 | **外部 AI 通过 MCP 用积微当长期记忆** | 同样的检索质量、权限分开 | 只有基础检索 |

**结论：S1、S2、S3、S12 的失败主要来自底座；S4–S10、S13 需要“按问题选办法”；S10 需要把更多个人数据纳入检索。** 第一版设计只覆盖了 S1–S3 和 S12 的一部分。

## 3. 实测（基于真实素材与本机模型）

| # | 发现 | 数据 |
|---|---|---|
| 1 | Word 文档被切成碎片 | 一份技术协议 1539 段，中位数 6 字，767 段不足 6 字（不进向量索引）；表格每格一段，条款与标题分开；7 份技术文档中 5 份的碎段占六到八成 |
| 2 | PDF 文字层中的康熙部首字符 | 课程资料包 PDF 中 8%–13.5% 的汉字是部首字符（`⼈` ≠ `人`），关键词检索大面积失效 |
| 3 | `.doc` 读不了 | 素材中 22 份；纯 JS 库 `word-extractor`（MIT）实测 22 份全部可读，单份 1–56 毫秒 |
| 4 | 页眉重复 | 57 页招标文件 55 页同一页眉；80 页论文 79 页同一页眉 |
| 5 | 扫描件与超大扫描书 | 4 份技术协议纯扫描（14–68 页）；古籍扫描本单册 640–840 页 |
| 6 | 相似文档与重复模板 | 十几份装配线协议都写“节拍”“验收”；两份岗位说明书合集几乎相同 |
| 7 | 跨语言语义检索 | 现有本地向量模型（EmbeddingGemma 2，512 维）在 504 段混合语料上：中文问英文论文 6 题中 5 题正确段落进前 3，与用英文问基本一致；1 题排第 15（“用草图生成关卡”这类需要推理的说法） |
| 8 | 关键词跨语言 | 中文问英文资料时关键词通道没有任何命中，融合时只靠向量一路 |

**判断**：向量模型不是主要瓶颈，不需要为“跨语言”马上换模型；但它在难的语义问题上排序不稳，需要精排，换不换模型要用评测决定（§8）。底座问题（#1–#5）收益最大。

## 5. 底座：读得懂、切得对、什么都能搜

### 5.1 解析与规范化（S1、S2、S12）
- **规范化**：康熙部首、部首补充、兼容汉字映射为标准汉字；全角字母数字转半角。只修正提取产物，不改作者内容。
- **Word**：`.docx` 按标题、编号条款（`第X章`、`一、`、`（一）`、`1.1.1`）、列表、表格还原结构；`.doc` 用 `word-extractor`。
- **PDF**：去页眉页脚、按行距和缩进还原段落、按字号和编号识别标题；页面分流允许同时需要表格和插图识别。
- **识别结果**同样规范化、按结构切分。
- **统一格式表**：类型、解析器、界面提示同一处定义；暂不支持的格式明确告诉用户怎么办。

### 5.2 切分与章节路径（S1、S2）
按结构切，中文约 300–700 字一段，不跨标题合并，过短的并入同节；每段存“资料标题 › 章 › 节”的路径，参与检索、显示在引用上；表格按行组切、每组重复表头。旧资料在空闲时自动重新整理，旧片段 ID 映射到新片段，批注、导图原文、历史引用继续可跳转。

### 5.3 资料卡（S3、S5、S7、S9）
每份资料一张卡：一句话说明、约 200 字摘要、关键词、资料类型（合同 / 论文 / 教材 / 课件 / 会议纪要 / 网页文章 …）、涉及的人和机构、文中日期、目录。
- **免费默认**：本地生成——目录来自章节路径，关键词用 TF-IDF，摘要取开头和各章首段，类型按文件名与结构规则判断。
- **更准（可选）**：设置“用模型整理资料卡”，用当前的低价模型生成；在 DeepSeek 低谷时段排队；“不给 AI”的资料只用本地方式；计入费用与上限。
- 资料卡单独建索引，用于“哪份资料讲了 X”、列举类问题、资料名定位，也显示在资料详情里。

### 5.4 把更多个人数据纳入检索（S10）
建立“知识来源注册”：每类数据声明怎样产出检索单元、时间、人物、隐私检查、打开位置。在笔记、资料、批注、笔记图片之外，新增：
- 错题（题干 + 错因 + 知识点）、收件箱条目、洞见、决策日志、存进积微的回答；
- 邮件：只有用户已连接的邮箱、且在设置中打开“邮件进入知识库”时；
- 过去的对话：默认不进入一般检索（避免 AI 自己的话被当作事实），只通过“查找过去的对话”工具在用户问“上次你怎么说的”时使用；无痕对话永不进入。
所有新来源都继承“不给 AI”、删除、附件隔离规则；AI 生成的内容降低权重并标明。

### 5.5 就绪状态（S12、S14）
每份资料显示能不能被检索（扫描件未识别、格式不支持、未转写、正在建索引），带一键补救；对话中涉及的资料未就绪时，模型如实说明范围，回答下方给出补救按钮。

## 6. 检索智能体：按问题选办法

### 6.1 理解问题
先用规则，规则判断不了的复杂问题再调一次低价模型（结构化输出，程序校验），得到：
- **类型**：查找 / 指定资料 / 比较 / 列举 / 整理成表 / 总结 / 媒体定位 / 找自己记过的 / 闲聊（不检索）；
- **对象**：问题里提到的资料（资料名定位）、人、项目、概念；
- **筛选**：时间（“上周”“去年 3 月”“最近”）、数据类型（“视频里”“论文”“会议”“错题”）、说话人；
- **检索用的问法**：原问题必须保留；追问时补上上一问的对象；问外文资料时补一份译文用于关键词通道。
用户明确选的范围是硬约束，任何改写都不能扩大。

### 6.2 各类问题的办法

| 类型 | 办法 | 完成条件 |
|---|---|---|
| 查找（S1） | 多路召回 → 精排 → 取证据 | 找到支持回答的原文 |
| 指定资料（S2、S3） | 资料总量在预算内（默认不超过模型上下文的 40%，且不超过 6 万词元）→ **整篇读**；更大 → 限定在该资料内检索，按需用 `source_read` 读前后文 | 范围内作答，说明读了哪部分 |
| 比较（S4） | 拆成每个对象一次限定检索，各自取证据，再一起回答 | 每个对象都有证据，缺的明说 |
| 列举（S5、S9） | 先在资料卡和笔记标题层面列出全部候选（可超过 8 个），给出清单与依据；用户要细节时再逐个看 | 明确列举口径，“没找到”不说成“没有” |
| 整理成表（S6） | 新工具“逐份抽取”：对选定的资料按同一组字段逐份读取抽取，汇成表格（智能界面表格组件），每格带出处；资料多时后台进行，先报预计用量请用户确认 | 每份资料都有结果或明确“未提及” |
| 总结（S7） | 有章节摘要缓存就直接用；没有就走后台整理，整理过程中每节的摘要存为“章节摘要”供以后问答复用 | 说明覆盖了哪些章节 |
| 媒体定位（S8） | 限定在转写稿，按时间点和说话人返回，引用可跳到时间点 | 给出时间点 |
| 找自己记过的（S10） | 笔记、收件箱、错题、批注优先，必要时查过去的对话 | 标明来源类型和时间 |
| 学习用途（S13） | 按子主题分组召回，去重，追求覆盖面而不是最相似 | 素材覆盖主题的主要方面 |

### 6.3 多路召回与精排
- **关键词**：在三字索引之外，新增**中文分词**的关键词索引（BM25 排序），解决“三字片段”既切不准词又不计词频的问题；三字索引保留做子串匹配；两字词和编号走精确通道。
- **向量**：保留现有本地模型；是否换成更强的模型（及维度）由评测决定，换模型时用分代索引平滑切换。
- **资料卡与资料名**：命中资料卡的资料，作为限定集合再做一次片段检索。
- **筛选**：时间、类型、说话人、资料范围在 SQL 层生效，不再“先取后滤”。
- **融合与精排**：倒数排名融合取约 50 条候选，交给本地重排序模型（Qwen3-Reranker-0.6B 或评测选出的同类模型，按需下载、可删除）精排；未安装或超时则直接用融合结果。
- **去重与多样性**：近似重复只留一条（标“另见”）；未限定范围时同一资料最多占 3 条。

### 6.4 证据与回答
- **证据量自适应**：按模型的上下文长度和问题类型决定给多少（查找约 8–12 段，比较每个对象约 6 段，列举给清单而不是正文），短片段补上同节前后文。
- **证据的样子**：`[n] 资料《标题》 › 章节 · 第 N 页 / 12:34`，同一资料的证据放在一起。
- **一轮不够时自动补一次**：比较或列举时有对象缺证据，针对缺的对象再检索一次（最多两轮，每轮必须有新证据）。
- **如实**：哪些资料没读到、哪些对象没找到、“库里没找到”与“库里没有”的区别，都写在回答里；需要时按现有规则提议联网。
- **引用校验**：回答里的编号必须来自本轮证据，否则去掉该编号并在日志记录。

### 6.5 工具（智能体与 MCP 共用）
| 工具 | 变化 |
|---|---|
| `knowledge_search` | 增加筛选：`sourceIds`、`kinds`（笔记 / 资料 / 错题 / 收件箱 / 邮件 / 洞见…）、时间范围、说话人、`mode`（自动 / 精确 / 语义）；结果带章节路径 |
| `source_find`（新） | 在资料卡层面找资料，返回资料清单（标题、类型、一句话说明、时间），用于列举和定位 |
| `source_read` | 资料在预算内时可以一次读完整篇 |
| `knowledge_extract`（新） | 逐份抽取成表（§6.2），写入前确认、计入费用 |
| `conversation_search`（新） | 查找过去的对话（不含无痕） |
| MCP 服务端 | 暴露 `knowledge_search`（含筛选）与 `source_find`，权限沿用按客户端授予 |

## 7. 基线升级清单（不再作为限制）

| 原有基线 | 为什么妨碍目标 | 升级 |
|---|---|---|
| 固定取 8 段、单次检索 | 比较、列举、总结、学习用途都不够 | 策略层 + 证据量自适应 + 补一次检索 |
| 只有片段一种粒度 | “哪份资料”“有哪些”“整本书”无从回答 | 资料卡、章节摘要缓存 |
| 只搜笔记和资料 | 用户记在错题、收件箱、邮件、对话里的东西搜不到 | 知识来源注册 |
| 三字关键词 | 不认词、不计词频、两字词失效 | 中文分词 BM25 + 子串 + 精确通道 |
| 向量 512 维、一种模型、先删后建 | 换模型会让全体用户长时间退化 | 按模型声明维度的向量表 + 分代索引；模型由评测决定 |
| 不用重排序（v0.4.3 的决定） | 当时只有 41 行笔记；资料多了以后难问题排序不稳 | 默认精排（评测确认收益与耗时后） |
| 小资料也切片检索 | 整篇读更准、更省事，现在的模型上下文足够 | 预算内整篇读 |
| `source_digest` 的结果只进笔记 | 整理过的内容不能再用于问答 | 章节摘要缓存 |
| 评测只有 40 题 | 不能代表任何真实场景 | 场景化评测（§8） |

## 8. 评测：按场景测，检索层和回答层都测

- **语料**：真实素材约 100 份（技术协议与招标文件、课程 PDF、合同模板、`.doc`、英文论文、识别后的扫描协议、10 段转写后的课程视频）+ **合成个人数据**（康奈尔笔记、批注、收件箱、错题、会议录音转写、邮件，按八种角色写，含时间与人物）。素材与题目都放在仓库外。
- **题目**：每个场景 S1–S15 至少 10 题，共约 250 题；每题标注类型、期望的办法、正确证据（资料名 + 原文小段，允许多处）、是否应回答“没有”。
- **检索层指标**：分场景 Recall@k、MRR、首条资料正确率、范围越界、列举类的召回率（列出了多少该列的）、耗时。
- **回答层**：80 题用真实 DeepSeek 端到端回答，另用一个模型按评分表打分（正确、完整、引用可核对、没读到是否说明），Claude 审查时抽查打分。
- **对比实验**（第一版本 P0 就做，不改产品代码）：向量模型（现有 512 维 / 同模型 768 维 / Qwen3-Embedding-0.6B / bge-m3）、重排序模型、中文分词方案、整篇读与切片检索。结论决定 v0.14.6 用什么。
- 每个版本都重测，**门槛按场景设**，不用一个总分掩盖问题。
