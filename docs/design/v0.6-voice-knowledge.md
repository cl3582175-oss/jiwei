# 语音知识采集：设计（v0.6.3–v0.6.4）

状态：待确认（2026-10-10）。在 v0.6 总体设计（`v0.6-browser-and-capture.md`）中，原 v0.6.3“课堂录音”升级为**语音知识采集**：把说过的话、上过的课、开过的会，经过确认，转化为能长期积累、互相关联、可检索、可复用的知识。

## 1. 三类场景，产出完全不同

| | 会议纪要 | 课堂笔记 | 个人随想 |
| --- | --- | --- | --- |
| 说话人 | 多人，需要区分是谁说的 | 以老师为主，偶有提问 | 只有自己 |
| 用户要的是 | 决定了什么、谁做什么、什么时候做完 | 学会知识点、记住考点、按时完成作业 | 把零散想法留下来，并和已有想法连起来 |
| 产出 | 议题、各方观点、**决策**、**行动项（负责人、截止日期）**、待定问题 | 知识结构、概念与定义、例子、老师强调的考点、问答、作业 → **康奈尔笔记与复习卡片** | 尽量保留原话的整理稿、想法、问题、计划 → **想法笔记、洞见候选、待办** |
| 去向 | 行动项进入复盘的行动项（闭环检查）；同一系列的下次会议开始时提醒上次的待办 | 复习（FSRS）、掌握度地图、学习者档案中的概念 | 每周复盘、洞见（猜想 → 相信 → 验证）、与旧笔记的关联 |
| 隐私 | 涉及他人：录音前提示告知 | 一般 | 最高：可以只做本地转写、不交给云端 AI |

## 2. 需求中的漏洞与补充

| # | 漏洞 | 补充设计 |
| --- | --- | --- |
| 1 | 模型给的说话人是匿名的 `[S01]`，不知道是谁 | **声纹登记与身份匹配**：用户登记自己的声音（“我”），常见的人（同事、老师）在第一次确认后自动记住。以后的录音自动标上名字，跨录音一致 |
| 2 | 说话人区分会出错（实测 7 句错 2 句） | **声纹复核**：每一段再算一次声纹（CAM++），与同一说话人的其他段比对，不一致就改正或标“待确认”。实测声纹能把这 2 句纠正回来；转写稿中可一键改说话人，可选只改一句或全部改 |
| 3 | 课堂和会议现场需要实时看到字幕，但 MOSS 是整段处理 | **两遍处理**：录制时用现有的 SenseVoice 近实时出字幕（预览）；结束后由 MOSS 精修（说话人、标点、热词），替换预览稿 |
| 4 | 超过 90 分钟的录音（整天培训、长课） | 按停顿切分（每段不超过 60 分钟，有重叠），分段处理后用声纹把各段的说话人对齐 |
| 5 | 线上会议、网课的声音不经过麦克风 | **系统音频采集**：macOS 用 ScreenCaptureKit 的音频，Windows 用回环采集；可以同时录麦克风和系统音频，分别作为“我”和“对方” |
| 6 | 专有名词识别错误（人名、术语、课程名） | **热词来自知识库**：自动把概念名、笔记标题、已登记的人名、本系列以往录音中的高频术语作为热词（MOSS 支持热词，实测“积微”“FSRS”识别正确）；用户的每次纠错也加入热词 |
| 7 | AI 提取的内容可能编造 | **每一项都必须有证据**：每条决策、待办、知识点都要引用转写稿中的片段（时间段）；没有证据的条目直接丢弃；审阅时点击条目即可回放那几秒 |
| 8 | 不同的人想从同一份录音得到不同的东西 | **视角（Lens）**：同一份转写可以用不同的视角反复整理，每次结果都保留并记录版本（见第 4 节） |
| 9 | 系列活动（每周例会、第 N 讲） | **系列**：录音可以归入系列。开始录音时显示上次的未完成待办；整理时带上前几次的摘要，前后连得上 |
| 10 | 相对时间（“下周三之前”）没法落到日程 | 以录音日期为基准换算成绝对日期，在审阅时标出换算结果，例如“2026-10-14（周三）” |
| 11 | 录他人的合规与隐私 | 会议场景开始录音时提示“请告知参会者”；录音默认本地加密存储，不进入云端同步；个人随想可设为“仅本地”（只转写和本地检索，不调用云端大模型） |
| 12 | 录音中途崩溃、断电 | 边录边分块写入磁盘（每 10 秒一块），崩溃后可以恢复到最后一块 |
| 13 | 录音时手动标记的重点比 AI 判断更可靠 | 录制界面提供三个标记按钮：★ 重点、✓ 决定、☐ 待办，打点记录时间，整理时作为强信号 |
| 14 | 录音来自手机 | 复用 v0.6.2 的手机扫码上传；手机网页也可以直接录音并上传 |
| 15 | 中英混说、方言 | MOSS 支持 50 多种语言和混说；方言效果需要实测（作为评估项） |

## 3. 实测：MOSS-Transcribe-Diarize 能否嵌入积微

**模型概况：**
- OpenMOSS 2026-07-09 发布，0.9B，Apache 2.0。
- 一次完成转写、说话人区分和时间戳，单次最长 90 分钟，支持热词和提示词。
- 获 INTERSPEECH 2026 MLC-SLM 挑战赛第一名。
- 官方评测中，中文会议数据集上的 cpCER 优于豆包、ElevenLabs、Gemini 等商用系统。
- 第三方评测（DiaScriber）：AliMeeting DER 4.1%、cpWER 16.2%。

**运行方式：**
- 官方推理依赖 Python、PyTorch 或 vLLM / SGLang（GPU），不适合嵌入桌面应用。
- 采用 **CrispASR**（MIT，基于 ggml）：
  - 提供 macOS（arm64、x64）、Windows（CPU / CUDA / Vulkan）、Linux 的预编译二进制，原生支持 `moss-diarize`；
  - 更新频繁，最近一次发布在 2026-10-08；固定版本并做 sha256 校验；
  - 可以通过 gh-proxy 镜像下载，与 llama.cpp 运行时的下载方式相同。
- 没有选 moss-transcribe.cpp：它没有预编译版本，7 月之后不再更新。

**实测**（Apple Silicon，CrispASR v0.8.42，MOSS Q4_K 1.19 GB）：
- 测试材料：用三种系统语音合成一段 45 秒的三人中文会议，包含决策、待办和术语，热词设为“积微、FSRS”。

| 项目 | 结果 |
| --- | --- |
| 文字 | 7 句**逐字全对**，标点正确，热词“积微”“FSRS”正确 |
| 速度 | 45.5 秒音频用时 13.2 秒（3.4 倍实时）；90 分钟的课约 26 分钟 |
| 内存 | 约 1.5 GB |
| 时间戳 | 段级，误差约 2 秒以内，足够“点击回放” |
| 说话人 | 7 句中 2 句错误（主持人的两句被标成第二个人） |
| 声纹复核（CAM++，28 MB，在现有 sherpa-onnx 中运行） | 同一人各句之间相似度 0.80–0.93，不同人之间 0.04–0.70；两句错误都能据此纠正 |

结论：

- 采用 MOSS-Transcribe-Diarize 作为录音精修的引擎，加上 CAM++ 声纹复核与身份匹配。
- 现有的 SenseVoice 保留，用于实时预览和单人短录音。
- 合成语音不能代表真实环境（嘈杂、回声、多人抢话），**开工前需要用真实录音再测一轮**：一场会议、一节课、一段随想，最好由你提供。

## 4. 同一份转写，不同的任务指令，完全不同的输出

### 4.1 转写是唯一的原始资料
- 录音存为一份资料，类型为“录音”。
- 转写稿按句分段，每句带说话人、开始和结束时间，可以纠错，纠错会保留。
- 所有整理结果都是从它**派生**出来的，不会覆盖原始转写。

### 4.2 视角 = 技能 + 输出结构 + 证据规则
每个视角是一个技能（沿用 v0.3 的 SKILL.md），包括：
- **任务指令**：这个场景下什么重要、什么不重要。比如会议看重决策与责任人，课堂看重概念与考点，随想要尽量保留原话。
- **输出结构**（zod）：用结构化输出强制填写，沿用现有的 `structured()`。
- **证据规则**：每一项都必须有 `evidence: 片段 ID[]`。程序校验这些片段存在且内容相关，不通过的条目丢弃。
- **落地规则**：
  - 会议的行动项 → 行动项；
  - 课堂的知识点 → 康奈尔笔记的行与复习卡片；
  - 随想 → 洞见候选、待办。

内置视角：

| 视角 | 输出（结构的要点） |
| --- | --- |
| 会议纪要 | 主题；参会人（对应说话人）；议题（要点、各方观点及发言人）；决策（内容、决定人、依据）；行动项（事项、负责人、截止日期）；待定问题；风险 |
| 课堂笔记 | 课程与讲次；知识结构大纲；概念与定义；例子；老师强调或考点（含原话与时间）；课堂问答；作业与截止日期 → 康奈尔笔记行（线索 = 问题，笔记 = 要点，出处 = 时间点） |
| 个人随想 | 整理稿（去口头禅、分段、加小标题，尽量保留原话）；想法；问题；计划；与已有笔记的关联（“和你 9 月的《X》相似或矛盾”） |

随取随用的轻量视角（同一份转写可以随时再跑）：
- 只要待办；
- 只要决策；
- 给缺席同事的三句话摘要；
- 生成复习题；
- 关于某个话题的所有讨论（例如“预算”）；
- 某个人说过的所有观点。

**自定义视角**：用户写一句指令，比如“列出客户提出的所有需求和顾虑”，结果满意可以保存为个人视角，下次直接用。

### 4.3 场景识别要“先问后猜”
- 开始录音时选择场景：会议 / 课堂 / 随想 / 自动。
- 选“自动”或导入文件时，用前几分钟的转写、说话人数量、时长、所属系列判断场景，并给出把握程度。把握不足时，审阅时请用户确认，不直接套用。

### 4.4 长录音的整理
- 90 分钟的课约 2 万字，在大模型的上下文范围内。
- 处理方式：先按话题切成几段，分别提取（带证据），再合并去重，最后生成整体结构。这样准确，也便于引用。
- 不急的整理可以排到夜间半价时段，复用 `isDeepSeekPeak`。

### 4.5 审阅：一切经过确认
- 左边是转写稿（按说话人着色，点击即播放），右边是提取结果。
- 点击任一条目，左边定位到证据并播放那几秒。
- 每条可以接受、修改或删除；行动项可以改负责人和截止日期。
- 接受后才写入笔记、行动项、复习卡片，沿用提案机制。

## 5. 交互流程

1. **开始。**入口有三个：侧栏“录音”、全局快捷键、笔记页的麦克风按钮。选择场景，可选择系列、参会人、额外热词；会议场景会提示告知参会者。
2. **录制中：**
   - 近实时字幕（预览）；
   - 标记按钮 ★ ✓ ☐；
   - 边录边记：右栏笔记的每一行自动记下录音时间；
   - 漏听时点“刚才说什么”，AI 用最近 60 秒给出一句话总结。
3. **结束后：**
   - 后台精修：说话人区分、声纹复核、热词，并显示进度；
   - **说话人确认**：“S01 是谁？”，播放此人的 5 秒原声，选择已登记的人、新建，或“这是我”。已登记的人会被自动认出，不再询问；
   - 选择视角整理 → 审阅 → 接受。
4. **之后：**
   - 检索时可以按人、场景、系列、日期筛选，例如“上周例会老李说过预算吗”；
   - 每个人有一个页面：一起参加过的会、交给他或她的待办、说过的观点；
   - 同一系列的下一次开始时，提示上次未完成的待办。

## 6. 数据与架构

| 层 | 做什么 | 用什么 |
| --- | --- | --- |
| 采集 | 麦克风、系统音频、导入音视频、手机上传；边录边分块写盘 | 渲染进程 MediaRecorder（Opus）；ScreenCaptureKit / WASAPI 回环（原生权限） |
| 预览 | 近实时字幕 | SenseVoice + VAD（已有） |
| 精修 | 转写、说话人、时间戳、热词 | **MOSS-Transcribe-Diarize** 加 **CrispASR**（固定版本、镜像下载、sha256，按需运行、用完退出） |
| 声纹 | 复核说话人、身份匹配、长录音分段对齐 | **CAM++**（3D-Speaker，28 MB，现有的 sherpa-onnx） |
| 理解 | 场景识别、视角整理、证据校验 | 云端大模型（`structured()`）；夜间批量 |
| 落地 | 笔记、行动项、复习卡片、概念、洞见、关联 | 提案机制 |

数据模型：

- 资料新增类型 `recording`，附场景、系列、参会人。
- `source_segments` 的分段类型为 `utterance`，定位为 `t=开始,结束`，并记录说话人。
- 新表：
  - `people`：人，含名字、是否本人、备注；
  - `voiceprints`：人的声纹向量，可有多条；
  - `recording_speakers`：每份录音中 S01 等标签对应到哪个人；
  - `series`：系列；
  - `derivations`：每次用视角整理的记录，含视角、版本、模型、时间、结果、证据。
- **声纹属于个人数据库，与记忆、学习者档案放在一起，不随知识库导出，可以一键清除。**

## 7. 风险

| 风险 | 对策 |
| --- | --- |
| 真实环境（嘈杂、多人抢话）的说话人区分效果不明 | 开工前用真实录音实测；声纹复核；界面上可快速改正 |
| CrispASR 版本更新快、接口可能变化 | 固定版本，做 sha256 校验；升级前先跑回归测试；保留 SenseVoice 作为退路 |
| Windows 的 CUDA / Vulkan 版本差异 | 默认用 CPU 版（最兼容），检测到可用的 GPU 时再提供加速版 |
| 系统音频采集需要系统权限 | 首次使用时说明用途；不授权时只录麦克风 |
| 录他人涉及隐私与法律 | 提示告知；默认只存本地；声纹单独存放，可清除 |
| AI 整理出错 | 证据强制校验；审阅后才写入；可以用其他视角重新整理 |
