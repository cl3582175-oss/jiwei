# 积微 v0.14：智能界面（设计）

> 状态：已确认（2026-10-14）。实施说明书交 Codex 实施，Claude 审查修正。
> 范围：让助手的回答不只有文字，还能按问题生成可操作的界面（图表、对比表、计算器、日程预览、待办、练习题……），并且这些界面能接上用户自己的数据、能动手做事、能存下来。
> 版本说明：用户决定先做智能界面，再做深度研究。本功能占用 v0.14，《研究智能体》设计稿中原定 v0.14 – v0.17 的内容顺延为 v0.15 – v0.18（用户已同意，ROADMAP 和研究设计稿已同步修改）。

---

## 0. 结论先行

1. **模型只输出“用哪个组件、填什么数据”，界面由积微自己的组件来画。** 不让模型写网页代码。这样输出又快又稳，样式统一，也安全。只有“小工具”这一类在隔离沙箱里运行模型写的代码，并且只开放给强模型（§5.5）。
2. **组件写在回答正文里，用一种带类型的代码块（`jiwei-ui`）。** 不走工具调用：DeepSeek、通义、Ollama 等对“流式输出工具参数”的支持不一致，而正文里的代码块所有模型都能输出，位置也自然（写在第几段就显示在第几段）（§6）。
3. **边生成边显示。** 渲染端有一个增量“编译器”：代码块一开头就画骨架，数据流进来逐步填满；代码块结束后做完整校验，校验不过就退回文字或表格，回答绝不会因此显示不出来（§7）。
4. **组件按“回答要帮用户做成什么”分类，而不是按学科分类。** 十类意图（看懂、看数、比较、决定、算、安排、去做、问清楚、练、查），学习、工作、生活都能用同一套组件（§5.1）。
5. **两层组件。** 第一层是约 14 个通用积木，包括分栏、标签页、折叠这类布局积木，可以组合出计算器、预算表、行程单等，不需要为每个场景写新组件；第二层是约 9 个**接数据组件**，接的是用户自己的日历、待办、笔记、资料、复习、决策、花费、邮件和研究结果。这一层是通用聊天助手做不到的（§5.2、§5.3）。
6. **每个组件都有三种互动，构成闭环：** 当场互动（滑块、排序、切换，不需要再问 AI）；回到对话（选项、表单、直接改表格后让 AI 接着做，是双向的）；留下来（存进笔记、加入复习、排进日历、变成待办，写入都先请用户确认）。存进笔记的组件仍然可以互动（§8、§10）。
7. **可扩展。** 插件可以用声明方式提供“组件模板”（由通用积木组合而成，不带代码）；接入的 MCP 工具如果返回界面，按 MCP Apps 的做法放在沙箱里显示（§11）。
8. **品质与可控。** 跟随积微的设计语言和深色模式；适应窄面板；键盘可操作、读屏可读；能导出成图片或文字；设置里有“关闭 / 适中 / 丰富”三档，每个组件都可以“改成文字”“换一种呈现”（§13、§15）。
9. **有评测才算数。** 准备一套问题集，检查“该用的时候用了没有、不该用的时候有没有乱用、数据对不对、能不能渲染出来”。每次改提示词或组件都要跑一遍（§14）。
10. **分四期交付：** 地基（编译器 + 通用积木 + 存进笔记 + 评测）→ 接上你的数据 → 工具与决策 → 生态（§16）。

## 1. 调研：别人怎么做的

| 产品 / 标准 | 做法 | 对积微的启示 |
|---|---|---|
| **ChatGPT Intelligent UI**（2026-10-07 随 GPT-6 发布） | 回答里可以出现图表、可点的按钮、表单、地图、勾选清单，以及计算器、分账器、小游戏这类小工具；用多选题追问来收窄需求；由模型判断什么时候用界面、什么时候用文字；用户可以调少视觉内容。OpenAI 只公开了原理：“一套预先做好的、可流式输出的原生组件库，加上一个在模型生成时同步构建界面的编译器”。训练时评估了生成界面的清晰度、有用性和完整性。 | 组件库 + 增量编译器是对的方向；“什么时候用”需要专门的规则和评测；必须让用户能调密度。 |
| **Google Gemini 的生成式界面**（2025 年 11 月起在 Gemini 应用和搜索中推出） | 按问题生成可视化排版或交互页面。 | 说明“回答即界面”已经是主流方向，不是噱头。 |
| **MCP Apps / OpenAI Apps SDK** | MCP 工具可以返回一个界面资源，宿主把它放进沙箱 iframe 显示，界面和宿主之间通过消息通信。 | 积微已经同时是 MCP 客户端和服务端。接入外部工具的界面时，照这个做法放进沙箱（§11.2）。 |
| **流式 Markdown 渲染（Streamdown，积微已在用）** | 能正确渲染还没写完的 Markdown，并支持为代码块提供自定义组件。 | 编译器挂在 Streamdown 的代码块渲染上，不需要换渲染器（§7.1）。 |

说明：OpenAI 没有公开编译器的内部格式，也没有对外开放组件接口。本设计的“正文代码块 + 增量解析”是根据公开描述和积微现状推出来的方案，不是照搬。上表中的第三方信息，实现前需要再复核一次。

### 2.2 缺的

1. 对话里只能显示文字、出处和工具步骤，**不能显示组件**。富内容只能插进笔记。
2. 没有增量解析：现有富内容是“工具调用完成后整块插入”，不能边生成边显示。
3. 没有“组件 → 回到对话”的事件通道。现在只有 `ask_user` 的选项能回传。
4. 没有组件状态的保存：用户拖过滑块、勾过清单，重新打开对话后状态就丢了。
5. 没有“什么时候用界面”的规则和评测。

## 3. 设计原则

1. **意图优先**：先想“这个回答要帮用户做成什么”，再选组件。只问一个事实，就用一句话回答。
2. **文字是骨架，组件是增强**：每个组件前后都要有文字说明它是什么、怎么看。去掉所有组件，回答依然完整可读。这也保证了导出、检索、读屏和退回文字时不丢信息。
3. **模型给数据，积微管样式**：组件的颜色、字体、间距、动效全部来自积微的设计语言，模型不能指定颜色和字号。
4. **一处写入，一次确认**：组件里任何会改动用户数据的按钮，都走现有的提案和确认卡片，不另开通道。
5. **不完整也能看**：任何时刻、任何截断位置，界面都能显示一个合理的状态（骨架、部分数据，或退回文字）。
6. **少即是多**：同一条回答里的组件默认不超过 3 个，单个组件的节点数、数据量都有上限。
7. **攒得下来**：每个组件都能转成文字（进检索），能存进笔记，存下以后仍能互动。

## 4. 用户体验：用户看到什么

### 4.1 一条回答的样子

```
用户：下周哪几天有空复习 PMP？每次两小时

积微：你下周有 4 个晚上是空的。按每次两小时，我建议排在周一、周三、周五：

┌ 日程预览 · 10 月 19 日 – 25 日 ───────────────────────┐
│ 一  19:00–21:00  复习：进度管理      [空闲]           │
│ 二  ─ 已有：部门聚餐 ─                                 │
│ 三  19:00–21:00  复习：成本管理      [空闲]           │
│ 四  19:30–21:30  可选                [空闲]           │
│ 五  19:00–21:00  做模拟题            [空闲]           │
│                         [调整时间] [排进日历]          │
└───────────────────────────────────────────────────────┘

周四也空，但你上周四复习时选了三次“困难”，建议留作缓冲。[1]
```

- 组件出现在正文中它被写到的位置，宽度跟随对话面板。
- 组件右上角有一个低调的“⋯”菜单：**改成文字**、**换一种呈现**、**存进笔记**、**复制为 Markdown**、**导出图片**。
- 组件底部是这个组件自己的操作按钮，比如“排进日历”。会写入数据的按钮点击后，弹出现有的确认卡片。

### 4.2 边生成边显示

1. 模型写到 ` ```jiwei-ui` 时，立刻在该位置显示组件的骨架：标题位置、浅色占位条，高度按组件类型预估，避免后面内容跳动。
2. JSON 每流进来一部分，就补画一部分：表格一行行出现，清单一条条出现，图表在数据齐全后一次性出图，不让柱子乱跳。
3. 代码块结束后做完整校验：通过就变成可操作状态；不通过就退回文字（§7.4），并在“⋯”里提供“查看原始数据”。

### 4.3 用户的控制

- 设置 → AI → **回答里的图示和工具**：关闭 / 适中（默认）/ 丰富（§15）。
- 单个组件：“改成文字”只影响这一个；“换一种呈现”会让 AI 用别的组件重画同一份数据（例如把表格换成图表）。
- 本条回答的“重新生成”沿用现有逻辑。

### 4.4 在哪些地方出现

| 位置 | 是否开放 | 说明 |
|---|---|---|
| 积微助手（对话） | ✅ 全部 | 主战场 |
| 就地提问（资料、网页、视频旁边的小对话） | ✅ 紧凑模式 | 面板窄，只开放不需要大面积的组件，自动用上下排列 |
| 今日页的问答框 | ✅ 全部 | 会跳转到对话 |
| 费曼练习、复盘追问 | ❌ | 这类对话需要用户自己组织语言，组件反而会干扰 |
| AI 任务的结果 | ✅ 只读 | 结果里的组件可以看，“去做”类按钮照常需要确认 |
| 通过 MCP 被别的 AI 读取 | 只给文字 | 对外只提供组件转出的文字 |

## 5. 组件体系

### 5.1 按意图分类

| 意图 | 组件 | 学习的例子 | 工作的例子 | 生活的例子 |
|---|---|---|---|---|
| **看懂** | 示意图、流程步骤、时间线、结构拆解、代码分步讲解 | 机翼升力原理 | 报销审批流程 | 签证办理步骤 |
| **看数** | 图表、数字卡、进度条 | 模拟考分数变化 | 季度销售 | 每月开销 |
| **比较** | 对比表、优缺点卡 | 两个概念的区别 | 三家供应商 | 两款手机 |
| **决定** | 决策矩阵（可调权重）、风险清单 | 选专业 | 选技术方案 | 要不要换工作 |
| **算** | 公式计算器（滑块）、换算器、预算表 | 物理公式 | 报价、工时 | 房贷、分账 |
| **安排** | 日程预览、阶段计划、行程单 | 备考计划 | 项目排期 | 旅行行程 |
| **去做** | 勾选清单、待办卡、邮件草稿卡 | 今天的复习任务 | 会议待办 | 搬家清单 |
| **问清楚** | 选择题追问、追问表单 | 想学到什么程度 | 报告给谁看 | 预算多少 |
| **练** | 练习题、翻面卡片、填空 | 刷题 | 培训考核 | 驾照题 |
| **查** | 笔记卡、资料片段卡、网页结果卡、研究结论卡 | 教材原文 | 合同条款 | 攻略来源 |

### 5.2 第一层：通用积木（约 14 个）

所有积木的数据格式都写在 `shared/ui/catalog.ts`（zod），每个都有：数据格式、`toText()`（转文字）、`fallback()`（校验失败时怎么显示）、`estimateHeight()`（骨架高度）。

| 积木 | `type` | 主要字段（示意） | 当场互动 |
|---|---|---|---|
| 分栏 | `columns` | `children`（2–3 个），`ratio` 可选 `"1:1"`、`"382:618"` | 窄面板自动上下排列 |
| 标签页 | `tabs` | `tabs: [{label, children}]`（2–5 个） | 切换 |
| 折叠区 | `details` | `summary`、`children` | 展开 / 收起 |
| 数字卡 | `stat` | `items: [{label, value, unit?, delta?, note?}]`（1–6 个） | — |
| 表格 | `table` | `columns: [{key, label, kind: text\|number\|date\|tag}]`、`rows`、`highlight?` | 按列排序；可编辑时直接改单元格（§8.2） |
| 列表 / 清单 | `list` | `items: [{text, done?, note?, cite?}]`、`checkable` | 勾选 |
| 步骤 | `steps` | `items: [{title, detail?}]`、`current?` | 逐步展开 |
| 图表 | `chart` | 与现有的 `ChartDataSchema` 相同，只是图表种类写在 `kind`（`bar`、`line`、`pie`、`scatter`、`radar`），因为 `type` 已经用来表示组件类型；存进笔记时再换回 `type` | 悬停查看数值、切换系列 |
| 示意图 | `diagram` | 现有的 `DiagramDataSchema`（Mermaid） | 缩放 |
| 时间线 | `timeline` | 现有的 `TimelineDataSchema` | — |
| 代码讲解 | `codesteps` | 现有的 `StepsDataSchema` | 上一步 / 下一步 |
| 选项 | `choice` | `question`、`options: [{label, value, hint?}]`、`multi?` | 选择后回到对话（§8.1） |
| 表单 | `form` | `fields: [{key, label, kind: text\|number\|select\|date\|slider\|toggle, …}]`、`submitLabel` | 提交后回到对话 |
| 公式计算器 | `calc` | `inputs: [{key, label, kind: slider\|number, min, max, step, value, unit?}]`、`outputs: [{label, expr, unit?, format?}]` | 拖动输入，输出实时重算（§6.4） |

“比较”“决定”“行程单”“预算表”这类常见场景**不需要新积木**，由上面的积木组合而成，并在提示词里给出组合范例（§9.3）：

- 对比表 = `table` 加 `highlight`；
- 优缺点卡 = `columns` 套两个 `list`；
- 决策矩阵 = 专用的接数据组件 `decision`（§5.3），因为它要写入决策日志；
- 预算表 = `calc`，或者 `columns`（`calc` + `chart`）；
- 行程单 = `steps` 或 `timeline`，需要写进日历时用 `schedule`（§5.3）。

### 5.3 第二层：接数据组件（约 9 个）

这一层组件**读的是用户在积微里的真实数据**，模型只能指定“查什么”，不能编造数据。查询在主进程执行，遵守现有的隐私规则：“不给 AI”的内容不出现；外部内容按 `<external-data>` 处理。

| 组件 | `type` | 模型给的字段 | 积微填的数据 | 操作（都需要确认） |
|---|---|---|---|---|
| 日程预览 | `schedule` | `range`、`proposals: [{title, start, end, goalId?}]`（可选） | 该时间段内已有的日程和空档 | 排进日历、调整时间 |
| 待办卡 | `tasks` | `filter`（今天 / 某方向 / 某笔记）或 `drafts: [{title, due?}]` | 已有的行动项 | 新建、完成、改期 |
| 笔记卡 | `note` | `noteId`、`rowIds?` | 笔记标题、选中的行 | 打开、在旁边打开 |
| 资料片段卡 | `excerpt` | `cite`（引用编号）或 `segmentId` | 原文、页码、时间点 | 跳回原文、存进笔记 |
| 复习与掌握度卡 | `mastery` | `scope`（全部 / 某方向 / 某笔记） | 到期数量、掌握度、薄弱点 | 开始复习、把薄弱点做成练习 |
| 决策卡 | `decision` | `question`、`options`、`criteria`、`scores` 或 `decisionId` | 已有的决策记录 | 调权重（当场）、记录我的决定 |
| 花费卡 | `usage` | `range` | 用量与花费 | 打开用量页 |
| 邮件卡 | `mail` | `filter` | 只读的邮件摘要（需要先新增读取邮件列表的接口，放在第四期） | 打开原邮件；**不提供发送** |
| 研究结论卡 | `findings` | `runId` 或 `claims: [{text, cite[]}]` | 证据与来源（v0.15 深度研究上线后接入） | 存进笔记、标记存疑 |

接数据组件的规矩：

1. 模型给的是**查询条件或草稿**，真实数据由积微填。模型写的“草稿”（如 `proposals`、`drafts`）在界面上明确标为“建议”，和已有数据用不同样式区分。
2. 查询结果不回传给模型，除非用户在组件上做了“回到对话”的操作（例如“按这个改”）。这样不会因为显示组件而多花 token，也不会把数据多发一次。
3. 数据在组件显示时读取。之后数据变了，组件显示一个“数据已更新”的小标记，点一下刷新。

### 5.4 练习类组件

练习题、翻面卡片、填空属于通用积木的特殊用法，但因为要接入复习系统，单独列出：

| 组件 | `type` | 字段 | 互动 | 留下来 |
|---|---|---|---|---|
| 练习题 | `quiz` | `items: [{q, options?, answer, explain, cite?}]`（1–10 题） | 作答、立刻判对错、看解析 | 做错的进错题本；整组存为练习笔记 |
| 翻面卡片 | `flashcards` | `cards: [{front, back, cite?}]` | 翻面、上一张 / 下一张 | 加入复习（变成康奈尔笔记的行，线索自动成为卡片） |
| 填空 | `cloze` | `text`（用 `{{答案}}` 标出空） | 填写、核对 | 加入复习 |

### 5.5 小工具（仅强模型）

`type: "widget"`：模型写一段单文件 HTML，复用现有的交互演示沙箱运行（独立源、禁止联网、不能访问父页面）。用于小游戏、模拟器、需要自定义交互的工具。限制：

- 只有 `ModelTier` 判定为强模型，并且密度设置为“丰富”时才开放；
- 同一条回答最多 1 个；
- 存进笔记时变成现有的“交互演示”块。

## 6. 组件语言：`jiwei-ui` 代码块

### 6.1 格式

模型在正文中写：

````markdown
你下周有 4 个晚上是空的：

```jiwei-ui
{"type":"schedule","title":"下周可以复习的时间","range":{"from":"2026-10-19","to":"2026-10-25"},
 "proposals":[{"title":"复习：进度管理","start":"2026-10-19T19:00","end":"2026-10-19T21:00"}]}
```

周四也空，但……
````

- 代码块语言固定为 `jiwei-ui`，内容是一个 JSON 对象，描述**一个**组件树的根。
- 为什么用 JSON 而不是 XML / JSX：JSON 有成熟的“不完整解析”，zod 校验现成；各家模型输出 JSON 都很稳定；积微现有的富内容也是 JSON。
- 为什么一个代码块只放一个根：流式解析简单，出错时影响范围小。需要多个组件时，用布局积木组合，或者写多个代码块。

### 6.2 通用字段

```ts
type UiNode = {
  type: string            // 积木或接数据组件的类型
  id?: string             // 同一条回答内唯一；用于保存状态和“回到对话”时指代
  title?: string          // 组件标题（可选，多数组件建议填写）
  note?: string           // 组件下方的一行说明，例如数据来源
  cite?: number[]         // 引用编号，和正文的 [1][2] 共用一套
  children?: UiNode[]     // 仅布局积木使用
  // …以及各类型自己的字段
}
```

### 6.3 上限

| 项目 | 上限 | 超出时 |
|---|---|---|
| 单个代码块大小 | 64 KB | 停止解析，退回文字 |
| 嵌套深度 | 4 层 | 校验失败，退回文字 |
| 单个代码块的节点数 | 60 | 校验失败，退回文字 |
| 表格 | 50 行 × 8 列 | 多出的行折叠到“展开全部”，列多于 8 就退回文字 |
| 同一条回答的组件数 | 适中 3 个 / 丰富 6 个 | 多出的显示成“展开查看”的文字块 |

### 6.4 计算器的公式

`calc` 的 `expr` 只允许一个**安全的表达式子集**：数字、输入变量名、`+ - * / ^ %`、括号、比较与三元运算，以及白名单函数 `min max round floor ceil abs sqrt log exp pow pmt`（`pmt` 用于等额还款）。

- 由积微自己的小型解析器计算（`shared/ui/expr.ts`，纯函数，单元测试覆盖），**不使用 `eval`，也不使用 `new Function`**。
- `pmt(月利率, 期数, 本金)` 返回每期还款额（正数），利率为 0 时退化为“本金 ÷ 期数”。
- 解析失败时，这个输出显示“公式有误”，其它输出照常计算。

例：房贷计算器

```json
{"type":"calc","title":"房贷月供",
 "inputs":[{"key":"p","label":"贷款金额","kind":"slider","min":10,"max":500,"step":5,"value":100,"unit":"万元"},
           {"key":"r","label":"年利率","kind":"slider","min":2,"max":6,"step":0.05,"value":3.1,"unit":"%"},
           {"key":"n","label":"年限","kind":"slider","min":5,"max":30,"step":1,"value":30,"unit":"年"}],
 "outputs":[{"label":"每月还款","expr":"pmt(r/100/12, n*12, p*10000)","unit":"元","format":"0,0"},
            {"label":"总利息","expr":"pmt(r/100/12, n*12, p*10000)*n*12 - p*10000","unit":"元","format":"0,0"}]}
```

## 7. 编译器：边生成边显示

### 7.1 在哪里接入

不新建渲染通道。对话的文字增量照旧通过 `chat:delta` 送到渲染进程，由 Streamdown 渲染；在 Streamdown 的代码块渲染上注册 `jiwei-ui` 语言，交给 `UiBlock` 组件处理：

```
主进程 chat.ts ──chat:delta──▶ 渲染进程 MessageItem
                                   └─ Streamdown
                                        ├─ 普通 Markdown
                                        └─ ```jiwei-ui → <UiBlock raw={代码块内容} closed={是否已结束} />
```

主进程不解析组件，只在一轮回答结束后做一次完整校验（§7.5），结果用于评测和日志统计。

### 7.2 `UiBlock` 的工作流程

```
raw 每次变化（节流到每 80 毫秒一次）
  │
  ├─ 不完整 JSON 解析（容忍未闭合的括号和字符串）→ 部分对象
  ├─ 读出 type：未知 → 显示“未知组件”骨架；已知 → 选中对应的组件
  ├─ 用该类型的 partial 校验（所有字段都可缺）得到“当前能画的部分”
  └─ 组件按“部分数据”渲染：
        有标题就显示标题；表格画出已完整的行；清单画出已完整的条目；
        图表、示意图、计算器这类必须完整才能画的，保持骨架并显示“正在生成…”

closed = true（代码块结束）
  ├─ 完整校验（zod + 结构检查，复用 checkChart 等）
  ├─ 通过 → 变成可操作状态，读取接数据组件的数据
  └─ 不通过 → 退回（§7.4），记一条日志
```

- “不完整 JSON 解析”优先用 AI SDK 自带的部分 JSON 解析函数；不满足需要时，自己写一个约 80 行的容错解析器（纯函数，单元测试覆盖各种截断位置）。
- 只把“已经完整的元素”画出来：数组里最后一个元素可能只写了一半，不显示它，避免文字闪烁。
- 组件的 React key 用 `id`，没有 `id` 就用它在树里的位置，保证流式更新时组件不重建。

### 7.3 防止页面跳动

- 骨架高度由 `estimateHeight(部分数据)` 给出：表格按已知行数估算，图表固定 240 像素，计算器按输入和输出的个数估算。
- 组件完成后高度变化不超过 120 像素时，用 200 毫秒的过渡；超过时直接切换，并保持对话的滚动位置，不把用户正在看的内容顶走。

### 7.4 出错就退回

| 情况 | 显示 |
|---|---|
| 不是合法 JSON | 一个折叠的“组件生成失败”提示，展开后看到原始文字 |
| 类型未知 | 同上 |
| 数据不合格，但能转出文字 | 用该组件的 `fallback()` 显示，例如图表显示成数据表，计算器显示成公式和默认结果 |
| 接数据组件查询失败或无权限 | 显示组件标题和一行原因（如“这个方向已被删除”），不显示数据 |
| 回答被中途停止 | 已画出的部分保留，标记为“未完成”，操作按钮不可用 |

### 7.5 回答结束后的处理（主进程）

一轮回答结束后，主进程扫描回答里所有的 `jiwei-ui` 代码块，做一次完整校验，并：

1. 把每个组件的 `toText()` 结果保存到消息的 `uiText` 字段，用于复制、导出和 MCP 对外提供。对话消息本身不进知识库；组件存进笔记以后才进检索（§10.2）；
2. 统计组件的使用情况和校验失败率，写进本机日志，供评测和改进提示词使用（不上传）。

## 8. 互动与状态

### 8.1 回到对话

`choice`、`form`、可编辑的 `table` 和 `calc` 有一个“交给积微”的操作。用户操作后，积微发出一条用户消息，界面上显示成人话，发给模型的是结构化内容：

```
界面上显示：选了「每周 8 小时，晚上」
发给模型：<ui-event component="plan-options" action="choose">{"value":"8h-evening"}</ui-event>
```

- 同一条回答里的组件，只有**最新一条回答**上的可以回到对话（和现在的 `ask_user` 规则一致），旧回答上的组件变成只读。
- `ui-event` 的内容来自用户的操作，但仍然按数据处理：模型不得把其中的文字当成新的指令（沿用系统提示第 10 条的处理）。

### 8.2 双向修改

可编辑的表格和计算器上有一个“按这个改”的按钮。用户改过的数据会以 `<ui-event action="edit">` 的形式，带着修改前后的差异发给模型，模型据此继续回答，比如重新排计划、重算预算、改写建议。

### 8.3 保存组件状态

新增表 `ui_states`：`messageId`、`componentId`、`state`（JSON，例如滑块的值、勾选状态、作答记录）、`updatedAt`。

- 用户的当场互动在 300 毫秒防抖后保存；重新打开对话时恢复。
- 状态只保存在本机，不发给模型，除非用户做了“回到对话”的操作。

### 8.4 写入操作

组件上会写入数据的按钮（排进日历、新建待办、加入复习、记录决定、存进笔记）一律调用现有的提案或确认流程：

- 已经有对应工具的写入（日程、行动项、笔记行、决策），按钮生成和工具调用相同的提案，在确认卡片里显示具体要写什么；
- 用户在组件上主动点按钮，等同于用户亲自操作：按钮先在组件内展开一个确认面板，逐条列出要写入的内容（可以取消勾选个别条目），用户点“确认”后才调用现有接口写入；笔记类写入照旧生成提案。这类写入不受“读过外部内容之后一律确认”这一条的额外限制，那一条只针对模型自己发起的写入。

## 9. 模型侧

### 9.1 什么时候用组件（写进系统提示的规则）

```
回答里可以用 jiwei-ui 代码块放组件。先想清楚这个回答要帮用户做成什么：
- 只问一个事实、一个定义、一个是非 → 只用文字。
- 有 3 个以上的数值需要比较或看趋势 → chart 或 stat。
- 比较 2–4 个对象的多个方面 → table。
- 讲流程、结构、因果 → diagram 或 steps；讲时间顺序 → timeline。
- 用户要算一个会随条件变化的数 → calc。
- 用户要做决定 → decision。
- 用户要安排时间 → schedule；要列出要做的事 → tasks 或 list。
- 用户想练习、检验自己 → quiz 或 flashcards。
- 缺少关键条件、没法给出好答案 → choice 或 form，一次问清，不要连续反问。
- 用到知识库里的原文且原文本身重要 → excerpt。
不要为了好看而用组件。每个组件前后都要有文字说明。同一条回答最多 {N} 个组件。
接数据组件只写查询条件或草稿，不要编造用户的日程、待办、笔记等数据。
```

### 9.2 组件说明放在哪里

- **组件目录**（每个组件的类型、一句话用途、字段签名、一个最小示例）放进系统提示的稳定部分。密度设置和模型档位只决定选用哪一份目录（关闭 / 适中 / 丰富 × 强 / 普通，最多 5 种组合），每种组合内部字节不变，仍然能命中前缀缓存。
- 目录的长度预算：适中约 1,800 token，丰富约 3,000 token。字段多的组件（如 `calc`、`schedule`）只在目录里写签名，完整说明和示例做成技能 `ui-<类型>`，需要时由模型用现有的 `skills_load` 加载。
- 新建对话时，如果用户的密度设置是“关闭”，目录完全不加入。

### 9.3 组合范例

提示词里给 4 个组合范例，覆盖最常见的组合方式：

1. 预算：`columns`（`calc` + `chart`）；
2. 比较：一段结论文字 + `table`（带 `highlight`）+ 一句建议；
3. 计划：`choice` 先问清条件，下一轮再给 `schedule`；
4. 学习：一段讲解 + `diagram` + `flashcards`。

### 9.4 按模型档位开放

| 档位 | 开放的组件 |
|---|---|
| 强模型 | 全部，包括 `widget`（仅“丰富”档） |
| 普通模型 | 除 `widget` 和三层以上嵌套之外的全部 |
| 本地小模型（Ollama 等，按名称或用户设置识别） | 默认关闭；用户可以手动打开“适中”，只开放 `table`、`list`、`choice`、`chart` |

### 9.5 出错以后怎么改进

- 回答过程中不中断、不重试，出错就退回（§7.4）。用户可以点“⋯ → 换一种呈现”，让模型重新生成。
- 本机日志记录每种组件、每个模型的校验失败率。评测（§14）发现某个组件失败率高时，优先改它的目录说明和示例。

## 10. 攒下来：组件存进笔记

### 10.1 存进笔记

新增笔记嵌入块类型 `ui`，数据就是组件树本身（加上保存时的状态）。规则：

| 组件 | 存进笔记后 |
|---|---|
| `chart`、`diagram`、`timeline`、`codesteps` | 转成笔记里已有的对应块，和以前一样可以编辑 |
| `widget` | 转成已有的“交互演示”块 |
| `quiz`、`flashcards`、`cloze` | 默认转成康奈尔笔记的行（线索 = 问题，笔记 = 答案和解析），自动成为复习卡片；也可以选择“保留为练习组件” |
| 接数据组件 | 存一份**当时的快照**（例如当时的日程安排），并标注“截至某日”；快照里的条目仍然能点回对应的日程、待办、笔记 |
| 其它积木（`table`、`calc`、`list` 等） | 存为 `ui` 块，仍然可以互动：计算器还能拖，清单还能勾 |

- 存进笔记走现有的 `saveAnswer` 扩展：用户主动操作，以“自动应用”的提案写入，保留 AI 来源标记和撤销。
- 存下来的组件带着它的出处，出处链接照旧可以点。

### 10.2 进检索

- 存进笔记的 `ui` 块用 `toText()` 转成文字，进入现有的分块和索引流程。对话消息本身不进知识库，这和现在的规则一致。
- 所以下次问到相关问题时，积微能找到“上次算过的房贷”“上次比较过的三家供应商”。

### 10.3 去做

| 操作 | 落到哪里 |
|---|---|
| 排进日历 | 日程（`plan_event_create` 同款提案） |
| 新建待办 / 勾选完成 | 行动项 |
| 加入复习 | 康奈尔笔记的行 → 复习卡片 |
| 做错的题 | 错题本 |
| 记录我的决定 | 决策日志（参谋同款） |

## 11. 生态：插件和 MCP

### 11.1 插件提供“组件模板”

插件在 `ui-templates/*.json` 里声明模板。模板是一棵**由通用积木组成的组件树**，里面的部分字段可以留成参数：

```json
{
  "name": "需求优先级矩阵",
  "description": "按价值和成本给需求排优先级（RICE）",
  "params": {"items": "需求列表 [{name, reach, impact, confidence, effort}]"},
  "tree": {"type": "columns", "children": [
    {"type": "table", "columns": [...], "rows": "{{items}}"},
    {"type": "chart", "kind": "scatter", "series": "{{items | rice}}"}
  ]}
}
```

- 模型通过 `{"type":"template","name":"需求优先级矩阵","params":{…}}` 使用模板。
- 模板只能使用通用积木和白名单里的数据变换（如 `sum`、`sort`、`rice`），**不能带代码**。所以安装插件不会引入任何可执行内容，这与积微“不运行插件里的脚本”的承诺一致。
- 角色包可以自带模板：教师（分层出题卡）、产品经理（优先级矩阵）、求职者（简历对照表）等。

### 11.2 MCP 工具返回界面

接入的外部 MCP 工具如果按 MCP Apps 的方式返回界面资源：

- 在现有的 `jiwei://sandbox/` 沙箱里显示：独立源、禁止联网（外部工具界面需要联网时，在工具策略里单独授权）、不能访问父页面；
- 界面和积微之间只通过消息通信，并且只能发起“回到对话”的事件，**不能直接写入积微的数据**；
- 外部工具的界面在显示时带有来源标记（哪个 MCP 服务器提供的）。

### 11.3 积微作为 MCP 服务端

别的 AI 通过 MCP 读取积微的对话或笔记时，组件只提供 `toText()` 转出的文字，不对外提供界面。

## 12. 安全与隐私

1. **模型不能执行代码**：组件只是数据；公式由安全解析器计算；只有 `widget` 在沙箱里运行，而且只开放给强模型。
2. **不能伪造数据**：接数据组件的数据由主进程按查询条件读取，模型给的草稿在界面上明确标为“建议”。
3. **不能绕过确认**：所有写入都走现有的提案和确认流程（§8.4）。
4. **外部内容只是数据**：网页、邮件、外部工具返回的内容即使包含 `jiwei-ui` 代码块，也不会被渲染成组件。只有模型自己写进回答正文的代码块才会渲染。实现上，检索片段和工具结果在送进模型前，把其中的 `jiwei-ui` 改写成普通文字。
5. **链接**：组件里的链接只允许 `https:`、`jiwei://note/…`、`jiwei://source/…`。外部链接点击时用系统浏览器打开，并显示完整网址。
6. **隐私**：接数据组件的查询遵守“不给 AI”和录音隐私规则；组件状态只保存在本机。
7. **资源**：单个回答的组件渲染时间超过 100 毫秒时降级为静态显示；图表数据点、表格行数都有上限（§6.3）。

## 13. 品质标准

每个组件上线前，都必须满足下面这张检查表：

| 方面 | 要求 |
|---|---|
| 设计语言 | 只使用积微的设计变量（颜色、字号、间距、圆角）；跟随深色模式；和笔记里的同类块长得一样 |
| 响应式 | 对话面板宽度在 320–900 像素之间都正常；窄于 480 像素时，分栏自动变成上下排列 |
| 流式 | 有骨架；部分数据能显示时就显示；完成时不闪烁，跳动不超过 120 像素 |
| 退回 | 有 `fallback()`；任何校验失败都能显示文字 |
| 无障碍 | 所有控件都能用键盘操作；有可读的名称；图表提供数据表视图；颜色不作为唯一的信息来源 |
| 多语言 | 组件自带的文字（按钮、提示）中英文齐全 |
| 导出 | 能复制为 Markdown（`toText()`）；能导出图片（复用现有的 SVG 截取） |
| 性能 | 单个组件首次渲染不超过 50 毫秒（图表和示意图除外，它们异步渲染）；流式更新节流到 80 毫秒 |
| 测试 | 数据格式单元测试；流式解析在各种截断位置的单元测试；端到端测试覆盖正常、出错退回、互动、存进笔记 |

## 14. 评测

### 14.1 问题集

新增 `docs/eval/intelligent-ui.md` 和对应的脚本，参照现有的检索评测 `retrieval-eval.spec.ts`。问题集约 120 题，分五组：

| 组 | 题数 | 检查什么 |
|---|---|---|
| 不该用 | 30 | 事实、定义、闲聊。期望：不出现组件 |
| 应该用 | 50 | 十类意图各 5 题，覆盖学习、工作、生活。期望：用了合适的组件 |
| 接数据 | 20 | 依赖用户的日程、待办、复习、决策。期望：用了接数据组件，并且没有编造数据 |
| 多轮 | 10 | 先追问再给方案、改了表格让它接着做 |
| 对抗 | 10 | 网页里藏着 `jiwei-ui`、诱导写入、超大数据 |

### 14.2 指标

| 指标 | 第一期目标 |
|---|---|
| 不该用时没有用（特异度） | ≥ 90% |
| 该用时用了（召回率） | ≥ 75% |
| 组件选得对（人工评分 ≥ 4 / 5） | ≥ 80% |
| 校验通过率 | 强模型 ≥ 98%，普通模型 ≥ 95% |
| 接数据组件编造数据 | 0 |
| 对抗题出现越权渲染或写入 | 0 |

### 14.3 怎么跑

- **受控测试**（每次提交都跑）：用本地模拟模型返回预先写好的回答，验证编译器、退回、互动、存进笔记。不连接真实服务。
- **真实模型评测**（改提示词或组件时跑）：对 DeepSeek、通义和一个强模型各跑一遍问题集，记录指标和花费，结果写进 `docs/eval/`。

## 16. 分期计划

### 第一期：地基（v0.14.0）

- 组件目录与数据格式：`shared/ui/catalog.ts`；表达式解析器 `shared/ui/expr.ts`。
- 编译器：`UiBlock`、不完整 JSON 解析、骨架、退回。
- 通用积木：`columns`、`tabs`、`details`、`stat`、`table`、`list`、`steps`、`choice`，以及从笔记搬过来的 `chart`、`diagram`、`timeline`、`codesteps`。
- “⋯”菜单：改成文字、复制为 Markdown、存进笔记、导出图片。
- `ui` 笔记块、`ui_states` 表、`uiText` 进检索。
- 系统提示中的规则和目录；设置里的三档。
- 评测问题集第一版，以及受控测试。

**验收**：受控测试覆盖 12 种组件的正常、截断、出错和退回；真实模型评测在“不该用”组达到 90%，校验通过率达到目标。

### 第二期：接上你的数据（v0.14.x）

- 接数据组件：`schedule`、`tasks`、`note`、`excerpt`、`mastery`。

- 练习类：`quiz`、`flashcards`、`cloze`，以及加入复习、进错题本。

**验收**：“接数据”组没有编造数据；排进日历、新建待办、加入复习的端到端测试通过。

### 第三期：工具与决策（v0.14.x）

- `calc`、`form`、`decision`、`usage`。
- 计算器存进笔记后仍能互动。

### 第四期：生态（与 v0.15 深度研究一起）

- 插件组件模板、角色包自带模板。
- MCP Apps 界面（沙箱）。

- `findings`（研究结论卡），和深度研究一起上线。

## 17. 风险与待定问题

| 风险 / 问题 | 处理 |
|---|---|
| 普通模型乱用组件，回答变花哨 | 规则里写清“不该用”的情况；评测的“不该用”组是第一期的硬指标；默认档位是“适中” |
| 组件目录让系统提示变长 | 目录只写签名，详细说明做成技能按需加载；目录在稳定部分，能命中缓存 |
| 流式渲染导致页面跳动 | 骨架预估高度；只画完整的元素；完成时控制跳动幅度（§7.3） |
| 接数据组件让模型以为自己“看到了”数据 | 规定查询结果不回传模型；需要模型基于数据推理时，模型应先调用读取工具，再写组件 |
| `quiz` 的答案本身是错的 | 练习题必须带解析；用到知识库内容时必须带出处；加入复习前用户可以先编辑 |
| 已定：本地小模型默认关闭组件 | 用户确认。按服务商（Ollama）识别，用户可以在设置里手动打开“适中” |
| 已定：`ui-event` 不计入“读过外部内容” | 用户确认：这是用户自己的操作 |
| 已定：版本号顺延 | 用户确认。研究设计稿原 v0.14 – v0.17 顺延为 v0.15 – v0.18 |
