# 对话附件设计（v0.14.4）

> 用户已确认（2026-10-14）：附件放在独立的“附件空间”；可人工归档（进入资料库）或删除；**既没归档也没删除的附件，只能在它所属的对话里使用，不能成为以后任何 AI 交流的信息源**；两期一起做，版本 v0.14.4（先于深度研究）；由 Codex 按说明书实施，Claude 审查。
>
> 起因：用户反馈各个 AI 对话窗口都不能直接上传附件，必须先去资料库导入、再回来提问。真实场景常常是“这次对话就围绕这份文件做一连串事”，来回切换既打断思路也不合理。

## 1. 现状

| 项 | 现状 |
|---|---|
| 对话窗口 | 积微助手对话页（`ChatView` 的 `Composer`）、工作区面板（`AiPanel`，笔记 / 浏览器旁）、就地提问的追问（`AnswerCard`）、费曼练习、复盘追问、参谋——都没有附件入口 |
| 已有的“附带内容” | 框选区域 / 视频画面作为图片发送（`ChatSend.images`，最多 4 张；不能看图的模型先本地识别文字）；输入框里贴网址可以让助手去读（v0.13）；对话范围 `scope: items` 可以指定资料库里的笔记和资料 |
| 资料管线 | `importPaths` 入资料库（按内容哈希去重）→ 分段（txt / md / pdf / docx / epub / html，图片走识别）→ 关键词 + 向量混合检索；音视频转写；扫描页和表格识别中有提示；`source_outline / 读段落 / source_digest` 让模型按需读长文档；回答引用可跳回原文 |
| 缺口 | 没有上传入口；pptx、xlsx / csv、doc、代码 / json 文件没有解析器；导入一定进资料库（一次性的文件会把资料库弄乱） |

结论：**底层管线大多是现成的，缺的是“对话里就地带上文件”的体验，以及几种常见格式的解析。**

## 2. 设计原则

1. **在哪问就在哪传**：所有能输入问题的 AI 窗口都能加附件，方式统一：📎 按钮、拖进窗口、粘贴（截图、复制的文件）。
2. **附件属于这次对话，而不是这一条消息**：传一次，后面的追问都能接着用，“针对这份文件做一系列要求”不用重复上传。
3. **附件空间，人工归档**：附件不进资料库，放在独立的“附件空间”。用户在那里决定每个附件的去向：**归档**（进入资料库，成为普通资料，以后所有对话都能用）或**删除**。
4. **不污染**：既没归档也没删除的附件，只对它所属的对话可见；不进入全局检索、相关推荐、知识图谱、发现与洞察、记忆、智能体工具、MCP 服务等任何别的 AI 来源。隔离靠“默认不可见、一处放行”的结构保证，而不是靠每处记得过滤。
5. **能马上问**：小文件发送前就解析好；大文件边处理边可以问，模型知道哪些部分还没准备好（沿用“扫描页识别中”的提示方式），不让用户干等。
6. **回答有出处**：引用附件的段落、页码、时间点，点一下跳到原文，和资料库资料一样。
7. **隐私一目了然**：附件内容会发给当前模型；第一次给云端模型发附件时提示一次；无痕对话的附件对话结束即清除，不进资料库、不形成记忆。

## 3. 用户体验

### 3.1 加附件
- 输入框左下角 📎（与“知识库”“联网”同一排），点开系统文件选择；
- 把文件拖到对话区域任意位置，出现“松开即可添加到这次对话”的覆盖层；
- 在输入框里粘贴：截图直接成为图片附件，复制的文件成为文件附件；
- 输入 `@` 可以从资料库 / 笔记里挑已有的内容，作为同一种“附件条”放进来（取代一部分“范围选择”的操作）。未归档的附件不在资料库里，不能被 `@` 到别的对话；要在别处用，先归档。

### 3.2 附件条（输入框上方）
每个附件一枚小卡片：类型图标、文件名、大小、状态，右上角 × 移除。状态依次为：
`正在添加 → 解析中 42% → 识别图片文字 / 转写中 → 可以提问`；失败时写明原因（格式不支持、文件太大、加密 PDF……）和可做的事。图片附件显示缩略图。

### 3.3 发送之后
- 用户消息气泡下方显示本条带的附件；点开即在阅读器里打开（PDF 跳页、视频跳时间）。
- 对话标题栏出现“本对话附件 N”，展开可以看全部、从本对话移除，或直接“归档到资料库”“删除”（与附件空间里的操作相同）。
- 新对话里如果第一条消息只有附件没有文字，给出贴合文件类型的起步建议：“总结要点 / 生成康奈尔笔记 / 出几道题 / 找出关键数据画成图 / 翻译”，点一下即发送。

### 3.4 各窗口
| 窗口 | 附件 | 说明 |
|---|---|---|
| 积微助手对话页 | ✅ 全部类型 | 主入口 |
| 工作区面板（笔记 / 浏览器旁） | ✅ 全部类型 | 例如“把这份讲义和我这篇笔记对照” |
| 就地提问的追问 | ✅ 图片、短文档 | 例如追问时贴一张题目照片 |
| 参谋 | ✅ 文档、图片 | 例如两份 offer、两份报价单放进来做决策 |
| 费曼练习、复盘追问 | 暂不做 | 这两处是用户自己讲、自己反思，附件会干扰练习目的；以后按需要再开 |

## 4. 模型怎么用附件（按大小与类型自动选择）

| 情况 | 做法 |
|---|---|
| 图片（截图、照片、手写） | 能看图的模型直接看图；不能看图的先本地识别文字；题目照片可以一键“加入错题本”（沿用错题流程） |
| 短文档（约 1.2 万字以内） | 全文作为外部数据放进上下文（`asExternalData`），回答最准确，不会漏检 |
| 长文档（书、长报告） | 不塞全文：把附件加入本对话的检索范围，模型用目录 / 读段落 / 后台整理工具按需去读；回答带页码引用 |
| 表格（xlsx / csv） | 解析为表格数据，小表全量给模型；回答里可以直接用 v0.14 的图表、表格组件呈现 |
| 演示文稿（pptx） | 按页取文字和备注，每页一段，引用到页 |
| 音频 / 视频 | 本地转写（已安装引擎时）；转写完成前可以先问，模型会说明“转写还没完成” |
| 代码、json、日志等纯文本 | 按文本处理，保留格式 |
| 不支持的格式 | 附件条上直接说明，不发送 |

实现要点：附件在主进程按“对话 ↔ 资料”关联（新表 `conversation_attachments`），每轮回答时，把本对话附件并入检索范围，并在系统提示里列出“本对话附件：《A》（已就绪）、《B》（转写中）”；短附件的全文只在需要时放入（首轮或用户点名时），避免每轮都重复发送、浪费费用。

## 5. 附件空间与数据

**附件空间**（资料库左栏新入口“附件空间”，独立于资料列表）：
- 列出所有附件：名称、类型、大小、来自哪个对话（可点开）、添加时间、状态（未归档 / 已归档到某分类 / 已删除）。
- 操作：归档到资料库（选分类，可批量）、删除（进入“最近删除”，可批量）、预览、打开所属对话。未归档数量在入口上显示为角标。
- 对话标题栏“本对话附件 N”里也可以直接归档或删除。

**数据**：附件仍是一条资料记录（复用解析、识别、转写、引用跳转），但 `sources.space = 'attachment'`；对话与附件的关系在新表 `conversation_attachments`。
- **默认不可见**：附件记录同时标记为不对 AI 开放（复用已有的“不给 AI”过滤，所有现有 AI 路径天然排除它）；所属对话通过专用通道读取。两处副作用单独处理：联网检索的隐私拦截不拿附件标题拦截查询；向量索引照常为附件建立（只供所属对话使用）。
- **归档**：改为 `space = 'library'`、恢复对 AI 开放、放进所选分类——从此和从资料库导入的资料完全一样。
- **删除**：进入“最近删除”；所属对话里显示“附件已删除”，不再发送其内容。
- **同一文件**：在同一个对话里重复添加只算一次；在另一个对话里再添加，复用同一条附件记录并建立新的对话关系（用户明确再次附上，才对那个对话可见）；已在资料库里的文件直接引用资料库的资料。
- **无痕对话**：附件不出现在附件空间、不建立向量；对话删除时彻底删除。
- **上限**：单条消息最多 10 个附件；文档单个 200 MB、音视频单个 2 GB；图片超过 8 MB 先压缩。

## 6. 需要补的解析器

| 格式 | 方案 | 依赖 |
|---|---|---|
| xlsx / xls / csv | 每个工作表转为表格段落，保留表头；超大表只取前若干行并告诉模型总行数 | 选一个成熟的表格解析库（实施前评估体积与许可证） |
| pptx | 按页取标题、正文、讲者备注 | 解析 OOXML（与 docx 同类） |
| doc（旧版 Word） | 能转换就转换，否则提示另存为 docx | 视评估结果 |
| 代码 / json / 日志 | 走纯文本解析，按行分段 | 无 |

## 7. 验收

- 每个窗口：按钮、拖放、粘贴三种方式都能加附件；状态正确；移除生效。
- 真实模型（DeepSeek 等）：PDF 教材（PMBOK 预览）追问 5 轮、引用页码正确；图片题目；xlsx 出图；pptx 按页总结；音频转写后问答；无痕对话结束后附件被清除。
- 资料库不出现未存入的附件；同一文件重复上传不产生重复资料；删除对话后附件按规则清理。
- 第一次向云端模型发送附件有提示；“不给 AI”的资料用 @ 引用时被拦下并说明。
